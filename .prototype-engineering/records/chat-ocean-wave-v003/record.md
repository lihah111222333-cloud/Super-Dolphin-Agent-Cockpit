# Prototype Record

## Changes from parent

- Existing thread work status now controls `chat-page--ocean-active`; running states accelerate and amplify the atmosphere, completed/idle states return it to calm motion.
- The reference day/night choreography is reproduced with a shared 1.8-second scene easing: sky/sea palette, sun-to-crescent mask, stars, clouds, and reflected light transition together.
- Every contour layer is nested inside and clipped by its owning wave.
- The broad direct-child positioning rule was replaced with explicit content-layer z-index targets, restoring the Notice overlay's fixed positioning.

## Assumptions

- Existing `workStatusForThread` is the canonical runtime truth for both Conversation busy presentation and ambient animation state.
- Chat history remains the scroll and drag safety boundary; the compact Agents card should overlay it rather than reserve layout space.
- The app-level theme toggle remains the only day/night source; the prototype adds no duplicate setting.

## Evidence

- Focused Vitest: 40 tests passed, including running-to-completed energy state, atmosphere structure, contour clipping, reduced motion, overlay positioning guard, and day/night scene coordination.
- Full frontend suite: 247 files / 3561 tests passed.
- `npm run lint` and `npm run build` passed; Vite production bundle synchronized successfully.
- LSP diagnostics reported no diagnostics for the edited JSX, test, and CSS files.
- Real browser CSS samples captured day, midpoint, and night values: stars `0 -> 0.690042 -> 1`, cloud opacity `0.75 -> 0.125515 -> 0.08`, light path `0.25 -> 0.534558 -> 0.6`, and moon mask moved continuously from `141.117px` to `83.1562px`.
- Real browser geometry showed Notice `position: fixed`, the Agents board `position: absolute`, and wave `overflow: hidden` in both light and dark themes.

## Findings

- A single shared runtime status mapping keeps conversation controls and atmosphere semantics aligned without DOM observation.
- The original Notice offset was a cascade regression from prototype CSS, not a defect in `ChatActionFeedback`.
- Reproducing the reference transition requires coordinated layer state; color-variable interpolation alone is perceptibly incomplete.
- The selected Chat history region is intentionally the message scroll and safe drag boundary. It does not allocate rows or columns to the Agents board; full Agents detail remains owned by the right panel.

## Known gaps

- Real-browser active-motion evidence was not generated by sending a new Agent message; the transition is covered by the canonical status adapter test and will be directly observable on the next real running turn.
- Exact animation phase is intentionally nondeterministic because the ambient loops continue from their current phase when durations change.

## Recommendation

Continue this direction for user acceptance. Keep it as a scoped prototype until active-state motion and day/night choreography are approved in normal chat use.
