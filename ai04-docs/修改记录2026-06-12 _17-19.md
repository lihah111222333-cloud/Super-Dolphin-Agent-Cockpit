# 修改记录 06-12 17:19

## 问题

触发 OpenAI API 报错：

```json
{
  "type": "invalid_request_error",
  "message": "The following tools cannot be used with reasoning.effort 'minimal': image_gen, web_search."
}
```

根因判断：Codex provider 允许并透传 `reasoning.effort = minimal`，但当前 Codex App / OpenAI 工具组合中，`minimal` 与 `web_search`、`image_gen` 不兼容。只要线程配置、全局偏好或单次 turn override 中带有 `minimal`，请求就可能被上游拒绝。

## 修改内容

### 后端 Codex App provider

- 新增 `internal/provider/codexapp/effort.go`
  - 增加 `normalizeCodexAppEffort`。
  - 将 `minimal` 规范化为 `low`。
  - 其它 effort 值只做 trim 后原样保留。

- 修改 `internal/provider/codexapp/support.go`
  - `thread/start` 构造参数时，对启动配置里的 `effort` 做规范化。
  - 覆盖全局偏好 / 启动配置中遗留 `minimal` 的路径。

- 修改 `internal/provider/codexapp/session_turn.go`
  - `turn/start` 构造参数时，对单次 `Overrides.Effort` 做规范化。
  - 覆盖线程或调用侧显式传入 `minimal` 的路径。

- 修改 `internal/provider/codexapp/session.go`
  - 当 turn 未显式传 effort、从 session runtimeConfig 回填 effort 时，也做规范化。
  - 覆盖已启动 session / 旧线程 runtimeConfig 中遗留 `minimal` 的路径。

### 前端新 UI

- 修改 `frontend-app/src/pages/settings/SettingsPage.jsx`
  - Codex provider 的 effort 下拉移除 `minimal / 极低`。
  - 读取到旧偏好 `minimal` 时规范化为 `low`，避免旧配置继续显示或保存危险值。

- 修改 `frontend-app/src/pages/chat/adapters/composerModelSelectorState.js`
  - 聊天页模型/推理强度选择器中移除 Codex 的 `minimal / 极低` 选项。
