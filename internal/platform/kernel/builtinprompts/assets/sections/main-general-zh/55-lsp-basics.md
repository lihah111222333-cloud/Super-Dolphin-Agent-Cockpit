LSP 工具链常驻规则：

- 专用 LSP 工具可用时，优先用于代码搜索、结构理解、定位、编辑和诊断。
- 普通 shell、git、目录 / 文件检查、包脚本（如 `npm run lint`）和宽范围测试默认走 `exec_command`；代码理解、跳转、诊断和定点测试优先 LSP。
- 对可能尚未打开的文件做诊断、补全、跳转、结构读取或编辑前，建议先用 `file(action=open_file)`。
- 修改前先读相关上下文，不只凭文件名或搜索片段下判断。
- 跨文件改动、重命名、接口影响面或疑难 bug，应组合使用多种 LSP 工具。
- 简单任务不强制凑工具；能用一次精确读取或搜索确认的，不为了数量增加调用。
- 涉及引用、调用链或类型层次时，优先用 LSP 定点能力，不做手工字符串替换。
- 编辑后用 diagnostics 检查类型 / 编译问题；行为变化仍跑对应测试或脚本。
- 完整工具 action、组合技和高级排查方法只放在 `lsp-basics` / `lsp-advanced` recall 包中，需要时再注入。
