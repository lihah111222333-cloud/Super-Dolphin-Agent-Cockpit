## 针对高风险的验证建议

### Provider identity / thread.start

建议新增或补强测试：

- `frontend-app/src/entities/client/model/useClientStore.test.js`
  - scoped preference 命中时不读 global。
  - scoped preference 缺失时 fallback 到 global。
  - scoped tombstone 阻断 global fallback。
  - `codexHome`、`codexInstanceKey`、`codexModelProvider` 缺任一字段时 fail-fast。
  - `settings.provider.active=claude` 的期望行为必须明确：报错、禁用，或真实发起 Claude。

- `internal/module/thread/start_session_guard_test.go`

## 优先级整改清单

### P0

1. Provider 支持面决策
   - 只支持 Codex：移除/禁用 Claude 入口，`settings.provider.active=claude` 应 fail-fast。
   - 支持 Claude：恢复 `claudecli.Module`，补 UI 到 provider 的端到端测试。

2. 锁定 provider identity 契约
   - 前端测试覆盖 scoped/global/tombstone。
   - Go 测试覆盖 nested config 和 strict decode。
   - PR 描述里明确 `thread/start` payload 形态。

3. 修复 Windows 构建可复现性
   - 替换 `Makefile:56` 的 `rsync`，或文档明确 Git Bash/WSL 依赖。
   - 给 `.ps1` runner 加与 `.sh` runner 对齐的启动顺序/默认 home 决策说明。

### P1

4. 拆分 UI 巨型文件
   - `useClientStore.js`：先拆 provider preferences、thread lifecycle、event handling。
   - `ChatPage.jsx`：先拆 timeline materialization、message rendering、layout/resizer。
   - `styles.css`：按 shell/chat/forms/dialog/workflow 页面分段，先建立目录和 import 规则，再移动。

5. 建立前端类型路线
   - 短期加 `jsconfig.json` 和 JSDoc typedef。
   - 中期把 `shared/api` 和 store preference helpers 迁移到 TS。
   - 迁移期间不做视觉 refactor 和类型迁移混合提交。

6. 增强 UI 错误可观测性
   - `runUIAction` 不再静默吞掉所有错误。
   - 统一写 frontend log 或 action notice。

### P2

7. 文档口径收敛
   - `README.md` Go 版本改为和 `go.mod` 一致。
   - `CLAUDE.md` 明确 `frontend-app` 是当前 UI，legacy Vue 只为 package-embed。
   - codemap 中容易过期的 package 数量改为“以源码为准”。

8. CI 和本地 wrapper 对齐
   - CI 使用 Makefile wrapper，或解释 raw `go vet/build ./...` 的理由。
   - Windows runner 加入轻量 smoke 验证。

9. 审查基准清洁化
   - 当前 3 个未提交文件在二次审查前处理清楚。
   - 合并前重新跑 `git status --short`，报告 HEAD 和 working tree 是否一致。
