# 项目脚本清单与作用分析

> 生成时间：2026-06-16  
> 分析范围：项目仓库内除 `.agents/skills/`、`.agent/skills/`、`skills/`、`internal/module/skill/embedded_skills/` 以外的脚本、脚本目录、Git Hook、CI 工作流和 `package.json` 脚本入口。  
> 排除范围：第三方依赖目录、构建产物、`.project-map/` 索引、普通业务源码文件。`*.json` 基线文件按脚本配套数据说明，不作为可执行脚本统计。

## 一、总体结论

本项目脚本主要服务于五类工作：

| 类别 | 主要路径 | 作用 |
| --- | --- | --- |
| 本地启动与调试 | `run-*.sh`、`run-*.ps1`、`frontend-app/scripts/*` | 启动新版 React 桌面端、旧版调试端、桌面烟测和前端契约检查。 |
| 质量守卫与 Git Hook | `Makefile`、`.githooks/*`、`.github/workflows/go-guard.yml`、`scripts/codex_stop_gate.sh` | 统一触发项目地图、提交信息、Go/前端/安全/发布守卫。 |
| 打包与发布 | `scripts/package_*`、`scripts/prepare_lsp_bundle_*`、`scripts/verify_packaged_app_*`、`scripts/publish_github_release.sh` | 构建 Linux/macOS/Windows 分发包、准备 LSP 运行时、校验产物并发布 GitHub Release。 |
| 契约、索引与迁移检查 | `scripts/*contract*`、`scripts/*codemap*`、`scripts/sqlite_release_gates`、`docs/security/*` | 生成或校验能力契约、代码地图、JSON-RPC 方法、SQLite 发布门禁和安全约束。 |
| 端到端与专项验证 | `scripts/*e2e*`、`scripts/*uat*`、`docs/scripts/*`、`cmd/agent-terminal/frontend/scripts/*` | 运行 DAG、LSP、提示词意图、P21、macOS 发布和旧前端专项验证。 |

当前建议把 `frontend-app/` 和 `run-new-ui-desktop.*` 视为主要本地开发入口；`cmd/agent-terminal/frontend/` 下的脚本仍保留为旧 Vue/Wails 前端的守卫与 E2E 工具。若后续做清理，应优先复核“疑似过期或需复核的脚本”章节。

## 二、入口调用关系

### 1. 本地开发入口

- `run-new-ui-desktop-hot.sh` 只是热重载包装器，设置 `SUPER_DOLPHIN_BACKEND_HOT_RELOAD=1` 后调用 `run-new-ui-desktop.sh`。
- `run-new-ui-desktop.cmd` 是 Windows 批处理入口，转调 `run-new-ui-desktop.ps1`。
- `run-new-ui-desktop.sh` 与 `run-new-ui-desktop.ps1` 是新版 `frontend-app` 桌面端的主要启动脚本，负责前端 Vite、Go 后端、端口、日志、临时 Codex Home 和热重载配置。
- `run-debug.sh` 与 `run-debug.ps1` 是旧版 `cmd/agent-terminal/frontend` 调试脚本，仍包含 Vue 模板检查、旧构建目标和交互式菜单。
- `run-new-ui-web.sh` 仍引用缺失的 `frontend/` 目录，当前更像历史遗留入口。

### 2. 守卫入口

- `Makefile` 是本仓库守卫命令的中心入口：
  - `make project-map` 生成 `.project-map/`。
  - `make guard-change` 调用 Go 项目变更守卫。
  - `make guard-commit` 先刷新项目地图，再执行提交前守卫。
  - `make guard-release` 执行发布前守卫。
- `.githooks/pre-commit` 会阻止提交 `.project-map/`，并在 Go、配置、工作流、Hook、技能相关文件变化时触发 `make guard-commit`。
- `.githooks/commit-msg` 校验提交信息必须符合中文主题和中文正文规则。
- `.github/workflows/go-guard.yml` 在 PR 和 `main` 推送时安装 Go 安全/质量工具并运行 `make guard-release`。
- `scripts/codex_stop_gate.sh` 是 Codex Stop Hook，按变更文件类型执行更窄的 Go、前端、脚本或 Hook 检查。

### 3. 打包发布入口

- 本地打包通常走平台本地包装器：
  - `scripts/package_linux_local.sh`
  - `scripts/package_macos_local.sh`
  - `scripts/package_windows_local.ps1`
- 本地包装器负责检查中继 bootstrap token、平台环境和 Codex/FFmpeg/LSP 前置条件，再调用主打包脚本：
  - `scripts/package_linux.sh`
  - `scripts/package_macos.sh`
  - `scripts/package_windows.ps1`
- LSP 运行时由 `scripts/prepare_lsp_bundle_linux.sh`、`scripts/prepare_lsp_bundle_macos.sh`、`scripts/prepare_lsp_bundle_windows.ps1` 准备。
- 打包后由 `scripts/verify_packaged_app_linux.sh`、`scripts/verify_packaged_app_macos.sh`、`scripts/verify_packaged_app_windows.ps1` 校验。
- GitHub Release 资产生成和发布分别由 `scripts/package_macos_github_release.sh`、`scripts/package_windows_github_release.ps1`、`scripts/publish_github_release.sh` 负责。

## 十、维护建议

1. 将 `run-new-ui-desktop.sh`、`run-new-ui-desktop.ps1`、`frontend-app/scripts/*` 标记为当前新版桌面端主路径。
2. 将旧前端 `cmd/agent-terminal/frontend/scripts/*` 的保留理由写入代码注释或迁移文档，避免后续误删仍被打包流程使用的脚本。
3. 对“疑似过期或需复核的脚本”先运行语法检查和最小 smoke，再决定修复、归档或删除。
4. 打包发布脚本涉及 bootstrap token、签名、公证和更新 manifest，应继续通过本地包装器进入，避免直接运行主打包脚本遗漏前置校验。
5. Git Hook 与 CI 已形成 `Makefile -> guard-* -> skill scripts` 的统一链路，新增守卫应优先接入 `Makefile`，不要散落为孤立命令。
