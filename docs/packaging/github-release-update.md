# GitHub Release Update Publishing

This flow publishes app-updatable artifacts to the GitHub latest release for
`xiaoxiaotest9527-bit/-`. This release flow covers macOS ARM64 DMG updates.

## Asset Contract

Each release staging directory must contain exactly these update assets before
publishing:

```text
Super-Dolphin-darwin-arm64.dmg
Super-Dolphin-darwin-arm64.update.json
```

The `.update.json` file is an Ed25519-signed manifest generated by
`cmd/super-dolphin-release-manifest`. It must point at the same tag's GitHub
release download URL for the DMG and must match the artifact size and SHA-256.

## Signing Requirement

Existing clients can install a new release only when the new manifest is signed
by the private key for the public key already embedded in the old package.

The publish script requires:

```bash
export SUPER_DOLPHIN_UPDATE_SIGNING_KEY=/private/path/to/ed25519.key
# Optional when one previous-package proof source below is set; otherwise required.
export SUPER_DOLPHIN_UPDATE_PUBLIC_KEY=<base64-encoded-32-byte-public-key>
```

It also requires one old-package proof source:

```bash
export SUPER_DOLPHIN_UPDATE_PREVIOUS_DMG=/path/to/old/Super-Dolphin.dmg
# or
export SUPER_DOLPHIN_UPDATE_PREVIOUS_APP="/Applications/Super Dolphin.app"
# or
export SUPER_DOLPHIN_UPDATE_PREVIOUS_ENV_FILE=/path/to/old/.env
```

If the previous package's `SUPER_DOLPHIN_UPDATE_PUBLIC_KEY` does not match the
current public key, publish, dry-run, and manual upload verification stop before
the release is accepted.
If `SUPER_DOLPHIN_UPDATE_PUBLIC_KEY` is omitted, the publisher reads it from the
previous package proof and uses that value for manifest verification.

## macOS Host

Run from the repository root on macOS ARM64:

```bash
export VERSION=v1.0.4
export SUPER_DOLPHIN_UPDATE_GITHUB_REPO=xiaoxiaotest9527-bit/-
export SUPER_DOLPHIN_UPDATE_CHANNEL=gray
export SUPER_DOLPHIN_UPDATE_MINIMUM_VERSION=0.0.0
export SUPER_DOLPHIN_UPDATE_PREVIOUS_DMG=/path/to/old/Super-Dolphin.dmg
# or: export SUPER_DOLPHIN_UPDATE_PUBLIC_KEY=<base64-encoded-32-byte-public-key>
export SUPER_DOLPHIN_UPDATE_SIGNING_KEY=/private/path/to/ed25519.key

./scripts/package_macos_github_release.sh
```

The wrapper calls `scripts/package_macos.sh`, embeds
`SUPER_DOLPHIN_UPDATE_GITHUB_REPO`, copies the DMG to the canonical asset name,
generates `Super-Dolphin-darwin-arm64.update.json`, and verifies the manifest
against the DMG.

`VERSION` is the Git tag and manifest version. The packaged app version defaults
to the tag without a leading `v`, for example `1.0.4`; override it with
`SUPER_DOLPHIN_PACKAGE_VERSION` only when the tag and package version must
intentionally differ.

## Publish

Use the macOS wrapper output staging directory, by default:

```text
dist/release/github/$VERSION
```

Before generating or uploading a new release, inspect the current GitHub latest
release:

```bash
./scripts/publish_github_release.sh --print-context
./scripts/publish_github_release.sh --inspect-latest
```

`--print-context` is a read-only diagnostic. It does not require `VERSION`, the
private signing key, or a local staging directory. It prints the GitHub latest
tag, the candidate `VERSION` status when set, whether that tag is greater than
latest, whether the candidate release already exists, the macOS remote asset
statuses, the local staging status when `VERSION` or
`SUPER_DOLPHIN_RELEASE_STAGE_DIR` is set, and whether the previous-package proof
and signing-key environment variables are configured. It never prints key
values.

`--inspect-latest` is a stricter read-only gate for the current GitHub latest
release. It verifies that GitHub latest currently exposes the DMG and its
macOS manifest with non-empty SHA-256 digests and positive sizes. It does
not verify manifest signatures; use `--dry-run` before scripted publishing and
`--verify-existing` after manual upload for signature and local-vs-remote digest
validation.

Then run:

```bash
export VERSION=v1.0.4
export SUPER_DOLPHIN_UPDATE_GITHUB_REPO=xiaoxiaotest9527-bit/-
export SUPER_DOLPHIN_UPDATE_SIGNING_KEY=/private/path/to/ed25519.key
export SUPER_DOLPHIN_UPDATE_PUBLIC_KEY=<base64-encoded-32-byte-public-key>
export SUPER_DOLPHIN_UPDATE_PREVIOUS_DMG=/path/to/old/Super-Dolphin.dmg

./scripts/publish_github_release.sh --dry-run
./scripts/publish_github_release.sh
```

The publisher validates that the tag is greater than the current GitHub latest
release, the DMG and manifest exist, the manifest verifies, `gh auth status`
can access the repo, and the uploaded GitHub asset digest and size match local
files. It creates a draft release first and only runs `gh release edit
--draft=false --latest` after the uploaded assets pass verification.

## Finding Release Inputs

Use these sources when preparing either scripted publishing or manual upload
verification:

- `VERSION`: choose the new Git tag, for example `v1.0.4`. It must be greater
  than the current GitHub latest release. The package version defaults to the
  tag without the leading `v`.
- Staged assets: generated by the macOS wrapper under
  `dist/release/github/$VERSION` unless `SUPER_DOLPHIN_RELEASE_STAGE_DIR` is set.
  Do not rename these files before upload.
- `SUPER_DOLPHIN_UPDATE_GITHUB_REPO`: use `xiaoxiaotest9527-bit/-` unless the
  release repository intentionally changes.
- `SUPER_DOLPHIN_UPDATE_PUBLIC_KEY`: read it from the previous trusted package:

```bash
grep '^SUPER_DOLPHIN_UPDATE_PUBLIC_KEY=' "/Applications/Super Dolphin.app/Contents/Resources/.env"
```

  If the app is not installed, mount the previous DMG and read the same
  `.app/Contents/Resources/.env` file, or point the publisher at that previous
  package with `SUPER_DOLPHIN_UPDATE_PREVIOUS_DMG`,
  `SUPER_DOLPHIN_UPDATE_PREVIOUS_APP`, or
  `SUPER_DOLPHIN_UPDATE_PREVIOUS_ENV_FILE`.
  For publish, dry-run, and manual upload verification modes, this environment
  variable may be omitted when one previous-package proof variable is set; the
  publisher derives it from that proof.
  The macOS asset-generation wrapper can also derive it from
  `SUPER_DOLPHIN_UPDATE_PREVIOUS_DMG`, `SUPER_DOLPHIN_UPDATE_PREVIOUS_APP`, or
  `SUPER_DOLPHIN_UPDATE_PREVIOUS_ENV_FILE`.
  If there is no local previous package, download and verify the current GitHub
  latest DMG, then use it as the previous-package proof:

```bash
./scripts/publish_github_release.sh --download-latest-previous-dmg /tmp
export SUPER_DOLPHIN_UPDATE_PREVIOUS_DMG=/tmp/Super-Dolphin-v1.0.3-darwin-arm64.dmg
```

The helper verifies the downloaded DMG against GitHub's asset SHA-256 digest
and size before printing the export line. Use the exact path printed by the
command; the example path above depends on the current latest tag.

- `SUPER_DOLPHIN_UPDATE_SIGNING_KEY`: find it on the release machine or secret
  store that generated the previous `.update.json` manifests. It cannot be
  recovered from GitHub release metadata, the public key, or a packaged app.
- `SUPER_DOLPHIN_UPDATE_MINIMUM_VERSION`: keep `0.0.0` unless there is an
  intentional minimum-version cutoff for older clients.

## Manual Upload Verification

If the two macOS assets are uploaded manually through GitHub, keep the local staging
directory unchanged and verify the published release before distributing it:

```bash
export VERSION=v1.0.4
export SUPER_DOLPHIN_UPDATE_GITHUB_REPO=xiaoxiaotest9527-bit/-
export SUPER_DOLPHIN_UPDATE_PREVIOUS_DMG=/path/to/old/Super-Dolphin.dmg
# Optional explicit value; it must match the previous package proof above.
export SUPER_DOLPHIN_UPDATE_PUBLIC_KEY=<base64-encoded-32-byte-public-key>

./scripts/publish_github_release.sh --verify-existing
```

This mode is read-only against GitHub. It verifies the local staged assets,
checks the same asset names on the existing GitHub release, compares the remote
asset digest and size with the local files, and requires the tag to be GitHub's
latest release. It does not create, edit, or publish a release, and it does not
need the private signing key. It still requires a previous-package proof so the
gate can prove old clients trust the update key. If
`SUPER_DOLPHIN_UPDATE_PUBLIC_KEY` is omitted, it is read from
`SUPER_DOLPHIN_UPDATE_PREVIOUS_DMG`,
`SUPER_DOLPHIN_UPDATE_PREVIOUS_APP`, or
`SUPER_DOLPHIN_UPDATE_PREVIOUS_ENV_FILE`.

After manual upload, run both read-only checks:

```bash
./scripts/publish_github_release.sh --print-context
./scripts/publish_github_release.sh --inspect-latest
./scripts/publish_github_release.sh --verify-existing
```

`--inspect-latest` catches missing or malformed GitHub assets without requiring
local staged files. `--verify-existing` is the stronger release gate because it
also validates signed manifests and compares every remote digest and size
against the local staging directory.
