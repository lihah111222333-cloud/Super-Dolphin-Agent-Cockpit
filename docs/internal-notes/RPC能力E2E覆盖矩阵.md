# RPC 能力 E2E 覆盖矩阵

本文档记录 headless `app.Run()` 可达 JSON-RPC method 的 E2E 覆盖状态。事实源是：

```bash
go run scripts/extract_jsonrpc_methods.go
```

## Status Contract

| Status | 含义 | 退出条件 |
|---|---|---|
| `covered` | 已有 subprocess black-box RPC E2E 覆盖 | 对应测试由 `make test-e2e-rpc-runtime` 或同等目标统一执行 |
| `planned` | method 已发现且已进入矩阵，但 E2E 用例尚未补齐 | 为该 capability family 增加 black-box RPC E2E，并把状态改为 `covered` |
| `blocked` | method 已发现，但当前缺少稳定 fixture、外部依赖隔离或安全执行边界 | 记录 blocker owner 和 exit condition，经主 agent 审查后再补 E2E |
| `desktop-only` | method 属于 Wails desktop-only RPC，不在 headless runtime 覆盖面 | 如需 headless 覆盖，先新增非 Wails runtime RPC contract |

> `blocked` 行默认 owner 为主控；`Fixture/dependency` 与 `Side-effect scope` 列记录 exit condition。主控分派到具体 agent 后，再更新对应行的 owner/exit condition 并推进状态。

## RPC Gaps

| Source | Methods or capability | Classification | Required test or exit condition |

| `internal/module/notify` | notification fanout without discovered host RPC method | `blocked` | Add explicit host RPC or document event-only contract with black-box event assertion |
| `internal/module/insight` | insight service feeds `dashboard/insights/list` and `dashboard/insights/approvals` through dashboard RPC | `planned` | Covered when dashboard insight RPC E2E seeds insight data and validates responses |
| `internal/module/turnobservation` | turn observation pipeline without discovered host RPC method | `blocked` | Add explicit observation RPC or event/log E2E assertion accepted by主 agent |
| `internal/module/unified` | unified service module without discovered host RPC method | `blocked` | Add explicit RPC if it is a user-visible runtime capability, otherwise record non-RPC contract |
| `internal/platform/toolbridge` | provider tool bridge uses MCP/tool callbacks rather than discovered host RPC method | `blocked` | Cover via toolbridge E2E or add host RPC contract if main-program RPC control is required |
