# TraceId Agent Diagnostics Closure - 2026-06-03

## Status

Implementation status: complete on integration branch `feat/traceid-agent-diagnostics`.

The host-direct MVP is implemented as `observability_trace_get`. Agents can use a user-provided `trace_id` as a structured tool input and receive a bounded, redacted `TraceDiagnosis` without reading local JSONL files directly.

## Implemented Behavior

- `internal/platform/observability/diagnose.go` exposes `DiagnoseTrace(ctx, TraceDiagnosisRequest)`.
- `DiagnoseTrace` requires `trace_id`, supports `limit`, `force_refresh`, `include_stack`, `cwd`, and `workspace_root`, and returns memory/tail source and freshness fields.
- JSONL tail diagnosis reports degradation, warnings, decode count, files scanned, bytes read, duration, timeout, and truncation.
- Model-facing output omits raw trace events and raw metadata, redacts secret-like and PII-like values, and normalizes in-workspace paths.
- `internal/platform/toolbridge/observability_trace_tool.go` registers `observability_trace_get`.
- Codex surface preparation advertises the tool only when tracing is enabled.
- Disabled or stale direct calls are handled by host dispatch and return a degraded diagnosis instead of falling through to peer tools.
- Host-direct output fills `ToolCallResult.StructuredContent` and mirrors the same JSON as `inputText`.
- Reserved host-only duplicate names and aliases from MCP peers are skipped; non-reserved duplicate names and alias conflicts still fail fast.

## Bounds

| Field | Implemented Value | Source |
| --- | --- | --- |
| Diagnosis default `limit` | 80 | `TraceDiagnosisDefaultLimit` |
| Diagnosis max `limit` | 200 | `TraceDiagnosisMaxLimit` |
| Serialized diagnosis payload | 256 KiB | `TraceDiagnosisMaxSerializedBytes` |
| String field max | 4096 bytes | `TraceDiagnosisMaxStringBytes` |
| JSONL tail query window | 20 MiB | `OBS_JSONL_QUERY_TAIL_MB` default |
| Tail query timeout | 750 ms | `OBS_QUERY_TAIL_TIMEOUT_MS` default |
| Tail query concurrency | 1 | `OBS_QUERY_TAIL_MAX_CONCURRENCY` default |

## Remaining Risk

The host-direct tool is available to Codex through the app graph and dynamic tool surface. Provider sessions that do not use that surface, or future non-Codex providers, still need either RPC parity or their own explicit tool wiring.
