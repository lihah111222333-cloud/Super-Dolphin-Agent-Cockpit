# 修改记录 06-13 15:24

## 需求

本次在 `internal/module/datasource` 增加文件数据源删除能力，用于移除当前项目工作目录下已经上传的文件数据源。

目标行为：

- 新增 RPC 接口 `datasource/delete`。
- 调用方通过文件名删除 `.agent/datasources/uploads` 目录中的对应文件。
- 删除范围必须限制在当前工作目录的数据源上传目录内。
- 参数非法、目标不存在、目标不是普通文件时都要显式报错，不做静默兜底。

## 接口设计

新增 RPC 方法：

```json
{
  "method": "datasource/delete",
  "params": {
    "fileName": "example.txt"
  }
}
```

成功返回：

```json
{
  "name": "example.txt",
  "deleted": true
}
```

`fileName` 只允许普通文件名，不允许：

- 空字符串。
- `.` 或 `..`。
- 绝对路径。
- Windows volume 路径。
- 带 `/` 或 `\` 的子路径。

## 修改内容

### 服务层

修改 `internal/module/datasource/service.go`：

- `Service` 接口新增 `DeleteFile(context.Context, DeleteFileRequest) (DeleteFileResult, error)`。
- 新增 `DeleteFileRequest`，字段为 `fileName`。
- 新增 `DeleteFileResult`，字段为 `name` 和 `deleted`。
- 新增文件名校验逻辑 `validateDeleteRequest`。
- 删除前使用 `os.Stat` 检查目标存在且是普通文件。
- 通过 `os.Remove` 删除 `.agent/datasources/uploads/<fileName>`。

错误语义：

- 非法 `fileName` 返回参数错误。
- 目标不存在保留 `os.ErrNotExist`，RPC 层映射为 not found。
- 目标不是普通文件返回参数错误，避免误删目录或特殊文件。

### RPC 层

修改 `internal/module/datasource/rpc.go`：

- `NewHandlers` 注册 `datasource/delete`。
- 新增 `deleteHandler` 调用服务层 `DeleteFile`。
- `datasourceRPCError` 增加删除相关错误映射。
