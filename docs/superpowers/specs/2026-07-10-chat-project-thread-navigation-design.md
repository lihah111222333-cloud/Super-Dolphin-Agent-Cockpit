# 聊天项目与会话两级导航设计

日期：2026-07-10

## 目标

1. “聊天页面”激活时，在同一侧栏内展示“项目 -> 会话”两级树形导航。
2. 输入栏中的项目控件成为可操作的项目选择按钮，并与侧栏使用同一项目状态。
3. 项目切换、会话切换和新建会话保持现有业务行为与错误传播方式。

## 非目标

- 不增加新的后端 RPC、线程协议或项目持久化格式。
- 不修改当前聊天消息、执行过程或附件选择逻辑。
- 不在非聊天页面常驻项目与会话树。
- 不引入新的 UI 框架或第二套项目状态。

## 信息架构

聊天侧栏使用同栏嵌套结构：

1. 主导航中的“聊天页面”保持一级页面入口。
2. 该入口激活时，其下显示项目列表；项目是第一级子栏目。
3. 展开项目后显示归属该项目的会话；会话是第二级子栏目。
4. 当前项目默认展开并高亮，当前会话在对应项目内高亮。
5. 离开聊天页面时隐藏项目与会话树，为其他页面释放侧栏空间。

项目树占用主导航与底部设置按钮之间的可滚动区域。品牌、新对话按钮、主导航和底部设置保持固定，不因长会话列表被挤出视口。

## 交互

### 项目与会话树

- 点击项目行展开或收起其会话列表。
- 展开项目时按现有缓存和加载逻辑获取该项目会话。
- 点击会话时先切换到对应项目，再打开该会话并保持聊天页激活。
- 每个项目保留新建会话入口；新会话归属该项目。
- 顶部“新对话”归属当前项目。
- 添加项目、重命名会话、归档或删除等现有操作继续复用原组件能力。

### 输入栏项目按钮

- 将当前只读的 `composer-context` 替换为现有 `ProjectSelector` 交互。
- 按钮显示当前项目名称和文件夹图标，并提供完整可访问名称与路径提示。
- 点击后打开项目菜单，可切换、添加或移除项目。
- 选择项目调用现有 `setActiveProjectPath`，侧栏项目高亮和会话列表随同一 store 状态更新。
- 项目名过长时省略显示，不得挤压模型与发送按钮。

## 组件边界

1. `SuperDolphinAgentSidebar` 负责决定何时展示聊天树，并向树传入当前 `projectPath`、store 和页面切换动作。
2. 现有 `SidebarProjectTree` 继续负责项目展开、会话加载、会话操作和项目级新建会话。
3. 现有 `ProjectSelector` 继续负责输入栏项目菜单，不复制项目选项生成或选择逻辑。
4. `ComposerMeta` 只负责将项目选择器放入工具栏，并保持附件、模型、发送动作的现有布局。
5. `useClientStore` 是项目和会话选择的唯一事实来源。

## 数据流

1. `AppShell` 现有 selector 已提供 `projects`、`activeProject`、`sidebarThreadsByProject`、`threads`、`activeThreadId` 及相关操作。
2. 项目树选择项目或输入栏项目菜单选择项目时，都调用现有 store 动作。
3. 项目树选择会话时，复用 `beginOpeningThread`、`setActiveProjectPath` 和 `setActiveThread` 的既有顺序。
4. store 更新后，聊天页、侧栏树和输入栏项目按钮通过订阅同步重渲染。

## 错误处理

- 添加项目、加载项目会话、新建项目会话或打开会话失败时，继续通过 `runUIAction` 和现有 warning/action notice 显式报错。
- 不为空项目、加载失败或缺失会话增加静默兜底数据。
- 加载状态和空会话状态在项目节点内显示，不阻塞其他项目展开。

## 响应式行为

- 桌面端在现有 280px 侧栏内显示两级树，不新增相邻侧栏。
- 项目名和会话名使用单行省略，操作按钮保持固定尺寸。
- 移动端继续使用现有侧栏抽屉；选择会话后关闭抽屉并显示聊天内容。
- 输入栏项目按钮在移动宽度下优先收缩文本，附件和发送按钮不缩小、不换行。

## 验证

- 模型/组件测试：聊天页激活时显示项目树，其他页面不显示。
- 组件测试：当前项目默认展开，项目下显示所属会话，当前会话高亮。
- 交互测试：项目、会话、新建会话、添加项目动作调用现有 store 方法。
- 输入栏测试：项目控件是可点击按钮，菜单可打开，选择后调用 `setActiveProjectPath`。
- 样式测试：树占据可滚动区域，底部设置固定；长项目名和会话名省略。
- 浏览器测试：桌面与移动宽度、明暗主题、中英文、多个项目和长会话列表。
