# Chat Turn 过程折叠与输入栏重绘设计

日期：2026-07-10

## 目标

1. 同一用户 turn 内只常显用户消息和最终 assistant 答复。
2. 将思考、工具调用、命令、计划及过程性 assistant 更新合并为一个默认折叠的“执行过程”组件。
3. 重绘消息输入栏，彻底消除附件文字挤压、工具栏换行和控件尺寸漂移。

## 非目标

- 不修改后端事件协议、RPC 或历史数据。
- 不处理当前会话同步、技能数据或 Codex transport 业务错误。
- 不改变附件选择、模型选择、发送和中断的业务行为。

## Turn 聚合

### 分组边界

时间线按现有顺序扫描。每条用户消息开启一个 turn，下一条用户消息结束前一个 turn。首条用户消息之前的孤立消息保持原顺序显示，不猜测归属。

每个 turn 中，最后一条非 reasoning、非 approval 且正文非空的普通 assistant 消息是常显答复。它之前的普通 assistant 消息以及 `thinking`、`reasoning`、`tool`、`command`、`process`、`plan` 消息进入该 turn 的过程集合。

当前仍在运行的最后一个 turn 使用同一规则：最后一条普通 assistant 消息常显并继续承载流式更新，之前的过程消息进入运行态折叠组件。尚未产生普通 assistant 消息时只显示运行态过程组件。

### 例外

- approval 消息始终独立常显，保证审批按钮可操作，不放入折叠区。
- 只有一条最终答复且没有过程消息时，不渲染空的过程组件。
- 没有最终答复但存在过程消息时，只显示过程组件。
- 用户附件继续跟随用户消息显示。

### 过程组件

新增 turn 级过程组件，使用原生 `details/summary`：

- 默认关闭，不持久化展开状态。
- 完成态摘要为“执行过程 · N 条”。
- 运行态摘要为“正在执行 · N 条”，带非侵入式状态指示。
- 展开后按原始时间顺序渲染每个过程项，并复用现有消息正文、reasoning、计划和工具展示能力。
- 折叠组件与最终答复共享会话内容宽度，不形成嵌套大卡片。

## 输入栏

输入栏保持单一面板，分为内容区和底部工具栏：

- 桌面宽度上限 900px，随内容区收缩；不使用页面全宽。
- 内容区默认高度约 76px，可随输入增长到现有最大高度。
- 工具栏固定单行、禁止换行，最小高度 48px。
- 附件按钮固定 36x36px，只显示 `Paperclip` 图标；`aria-label` 和 `title` 保留完整“添加文件”语义。
- 项目控件允许收缩并省略文本；模型控件保持可点击且限制最大宽度。
- 发送或中断按钮固定 40x40px，始终位于最右侧。
- 已选附件仍在输入区上方以可移除条目显示，不塞入工具栏。
- 明暗主题共享结构和尺寸，仅颜色使用现有 token。

移动宽度下仍保持同一行：附件和发送按钮不缩小，项目与模型优先截断；不得让任何文字竖排或覆盖相邻控件。

## 组件边界

1. 新增纯模型函数，将有序消息转换为用户消息、过程集合、approval 和最终答复组成的渲染项。
2. `ConversationTimeline` 只消费渲染项，不修改 store 中的原始消息。
3. turn 过程组件负责展开状态与过程项展示。
4. `ComposerMeta` 继续负责业务动作，结构只移除附件可见文字。
5. 输入栏尺寸和响应式行为集中在现有 composer/workbench CSS 中，避免新增 UI 框架。

## 验证

- 模型测试：多 turn、仅最终答复、仅过程、运行中 turn、approval 例外、首个用户前孤立消息。
- 组件测试：过程默认关闭，展开后过程可见，最终答复常显，approval 按钮不被折叠。
- 输入栏测试：附件按钮只有图标但仍具备可访问名称；项目、模型、发送动作保持不变。
- 样式测试：工具栏不换行，附件和发送尺寸固定，文本区和面板宽度符合约束。
- 浏览器测试：桌面和移动宽度、明暗主题、长项目名、长模型名、空输入和已有附件状态。
