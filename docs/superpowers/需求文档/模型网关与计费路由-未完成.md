# 模型网关与计费路由需求（未完成）

## 状态

未完成。本文把模型网关从账号充值需求中单独拆出，因为 Super-Dolphin 的商业本质是通过自有账号体系售卖上游模型 token。后续需要补充协议细节、数据库表和部署方案。

## 背景

客户端不能直接配置或暴露上游 provider token。否则无法稳定计费、无法控制模型权限，也无法避免用户绕过充值体系。

模型网关是客户端和上游模型之间的唯一服务端入口，负责账号校验、模型映射、上游 token 调度、用量结算、失败回滚和运营配置。

## 目标

- 客户端只认识 Super-Dolphin 的模型名和账号权益，不接触真实上游 token。
- 网关按账号状态、余额、套餐和模型权限决定是否允许请求。
- 网关把客户端模型名映射到真实 provider、模型名和 token 池。
- 网关记录每次请求的 token usage、倍率、扣费和错误。
- 网关支持运营后台配置模型、倍率、上游 token、路由优先级和禁用状态。
- 上游失败时必须释放预扣额度或回滚扣费。

## 核心模块

### 1. 客户端网关 API

- 模型列表：返回当前账号可见模型、可用状态、不可用原因和消耗倍率。
- 模型请求：接收聊天、Agent 或任务请求，并转发到网关内部路由。
- 用量刷新：返回剩余额度、套餐、试用状态和最近消耗。
- 请求结果：返回模型输出、实际消耗、剩余额度和错误分类。

### 2. 权益校验

- 未登录试用账号只允许基础模型和基础额度。
- 已登录账号按余额、套餐、模型权限和功能开关放行。
- 余额不足、模型未解锁、账号冻结、试用额度耗尽时直接阻断。
- 校验结果必须可解释，前端能展示“充值/升级/登录/稍后再试”等明确动作。

### 3. 模型路由

- 客户端模型名映射到真实 provider 和模型。
- 支持 provider 优先级、权重、可用状态、限流状态。
- 支持模型倍率配置，不同模型消耗不同额度。
- 支持禁用模型但仍在客户端可见，用于引导充值或升级。

### 4. 上游 token 池

- 记录 provider、token 标识、状态、剩余额度、错误率、最后使用时间。
- 支持启用、禁用、冻结、备注。
- 支持失败熔断和人工恢复。
- 不向客户端返回真实 token、真实 key 或可复用签名。

### 5. 用量结算

- 请求前预扣或额度冻结。
- 请求后按实际上游 usage、模型倍率和内部计费规则结算。
- 失败时释放预扣或退款。
- 重试时避免重复扣费。
- 支付、手动调整、模型消耗都进入统一用量流水。

### 6. 运营后台

- 模型列表和启停。
- 模型倍率配置。
- provider 和 token 池管理。
- 路由优先级配置。
- 账号用量、订单、失败率、扣费流水查询。
- 手动补额度、扣额度、冻结账号、解冻账号。

## 关键流程

### 获取模型列表

1. 客户端请求 `gateway/models/list`。
2. 网关识别登录态和账号权益。
3. 返回模型列表，每个模型包含可见状态、可用状态、倍率和不可用原因。
4. 前端展示所有主要模型，未解锁模型置灰并提示充值或升级。

### 发起模型请求

1. 客户端提交模型请求到 `gateway/chat/completions` 或等价私有接口。
2. 网关校验账号、余额和模型权限。
3. 网关冻结额度或生成待结算流水。
4. 网关选择 provider、真实模型和上游 token。
5. 网关调用上游 provider。
6. 网关读取 usage，完成结算。
7. 网关返回结果、消耗和剩余额度。

### 上游失败

1. 上游返回限流、鉴权失败、超时或服务错误。
2. 网关记录 token 状态和错误分类。
3. 可重试错误按策略选择另一个 token 或 provider。
4. 最终失败时释放预扣额度。
5. 前端只展示用户可理解原因，不暴露上游 token 信息。

## 不做

- 第一版不对第三方开发者开放公开 API。
- 第一版不做复杂多租户组织结算。
- 第一版不做上游 token 自动采购。
- 第一版不让客户端自行添加上游 API key 作为主路径。
- 第一版不承诺所有 provider 协议完全兼容。

## 接口草案

- `gateway/models/list`：获取当前账号可见模型和权限状态。
- `gateway/chat/completions`：聊天或 Agent 模型请求入口。
- `gateway/usage/estimate`：请求前估算消耗，可选。
- `gateway/usage/current`：刷新剩余额度和套餐状态。
- `admin/gateway/models`：运营后台模型配置。
- `admin/gateway/routes`：运营后台模型路由配置。
- `admin/gateway/tokens`：运营后台 token 池管理。
- `admin/gateway/usage-ledger`：运营后台用量流水。

## 前端验收标准

- 客户端模型列表能展示可用、未解锁、余额不足、试用限制等状态。
- 未登录试用只能使用基础模型。
- 登录后可刷新权益并展示更多模型。
- 充值成功后模型权限和剩余额度即时刷新。
- 客户端任何位置都不需要用户配置上游 token。
- 错误提示能引导用户登录、充值、升级或稍后重试。

## 后端验收标准

- 所有客户端模型请求都经过网关。
- 所有请求都记录账号、模型、provider、usage、倍率、扣费和状态。
- 上游 token 不会返回到客户端日志、响应体或前端状态。
- 支付回调、手动调整和模型消耗进入统一流水。
- 失败和重试具备幂等保护，避免重复扣费。
- 运营后台可以禁用某个模型、某个 provider 或某个 token。
