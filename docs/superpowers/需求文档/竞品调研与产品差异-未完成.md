## 调研结论摘要

Super-Dolphin 不应该照抄任何一个竞品。推荐定位是：账号化、可充值、可运营的本地 Agent 工作台。

- 学 Hermes：多项目、多会话、多 agent 的工作台感，每个 session 有独立模型、权限、cwd 和历史。
- 学 Codex：把任务、worktree、云/本地环境、技能和自动化包装成工程交付闭环。
- 学 Cursor：用显式上下文、文件/目录引用、规则和可视化状态降低模型误读。
- 学 Claude Code：会话恢复、fork、compact、权限模式、工具执行和本地历史记录的清晰边界。
- Super-Dolphin 自己要强化：账号试用、充值、模型网关、运营后台和上游 token 管控。

## Hermes 初步拆解

Hermes IDE 的公开页面强调：

- 桌面 IDE 形态。
- 多项目同时打开。
- 每个 session 有自己的 agent、模型、权限、cwd 和历史。
- Claude 原生 Agent mode，把 thinking、tool calls 和 diffs 作为一等 UI，而不是终端文本。
- Codex、Gemini、shell 和脚本可以作为 terminal mode 并行使用。
- git worktree 是一等概念，修复分支和功能分支可以并存。

对 Super-Dolphin 的启发：

- 主 UI 应该是 session/workshop，而不是后台菜单集合。
- 每个会话要展示模型、权限、cwd、历史、上下文和执行状态。
- 工具调用、diff、命令和产物要产品化展示，不能只显示日志。
- 多项目和多会话是重要方向，但第一版可以先做信息架构，不强行做复杂并行。

不建议照抄：

- 不把第一版做成完整 IDE 替代品。
- 不把所有 provider 都作为终端模式简单塞进去。
- 不优先做复杂主题、窗口管理和编辑器能力。

## Codex 初步拆解

Codex 的公开产品页强调：

- coding agent 帮助构建和交付软件。
- 支持多 agent 工作流、worktrees 和云环境。
- Skills 让 agent 适配团队标准、代码理解、原型和文档。
- Automations 支持后台自动处理例行任务。
- 同一账号连接 app、editor 和 terminal 等多端体验。

对 Super-Dolphin 的启发：

- 产品叙事要围绕“交付工程结果”，不是只围绕聊天。
- Skills、Prompt、Memory 应该被包装成“项目规范/工作流能力”，而不是工程配置页。
- 产物、验证、提交、继续本地处理，是主工作台必须可见的闭环。

不建议照抄：

- 第一版不做完整云任务系统。
- 第一版不做自动化常驻任务和后台 monitor。
- 第一版不承诺企业级协作。

## Cursor 初步拆解

Cursor 的上下文文档强调：

- 自动拉取相关上下文。
- 用户可以通过 `@file`、`@folder`、`@code` 等显式指定上下文。
- Rules 是长期、可复用、可作用域化的上下文。
- 大文件和大目录需要被压缩、裁剪或以概要方式进入上下文。

对 Super-Dolphin 的启发：

- UI 必须让用户知道“模型现在看到了什么”。
- 文件、目录、Memory、Prompt、Skill 的生效状态要可见。
- 上下文风险应提示，但不要新增独立复杂产品模块；先并入主工作台和 UI 重构。

不建议照抄：

- 不把上下文体验完全做成编辑器内联能力。
- 不承诺和 Cursor 一样的自动代码索引能力，除非后续明确实现。

## Claude Code 初步拆解

Claude Code 的文档强调：

- 工具让 agent 可以读写文件、执行命令、搜索、使用外部服务。
- session 保存在本地，可以 resume 和 fork。
- 新 session 是新上下文窗口。
- context 满时会自动管理，支持 compact 指令和 `/context` 查看占用。
- 权限模式和 checkpoint 是安全体验的一部分。

对 Super-Dolphin 的启发：

- 长会话承接必须区分 resume、fork、summary、provider compact。
- 本地 session 历史、runtime config、cwd、权限和产物是恢复现场的一部分。
- Super-Dolphin 作为 harness 不能宣称自研模型级压缩，只能适配 provider 能力或生成承接材料。

不建议照抄：

- 不直接复制 slash command 作为主要入口。
- 不把复杂权限模式放到第一版普通用户主流程。

## Super-Dolphin 差异点

### 必须强化

- 账号试用和充值闭环。
- 模型网关和上游 token 隐藏。
- 可运营的后台配置。
- 统一模型列表和权益展示。
- 产物化工作台，而不是终端日志。
- 长会话恢复和承接材料。

### 可以弱化

- 完整 IDE 编辑能力。
- 多窗口复杂管理。
- 企业团队协作。
- 公开 API 平台。
- 常驻自动化和监控。

## 推荐产品表达

Super-Dolphin 第一版可以这样表达：

> 一个可试用、可充值、可运营的本地 AI Agent 工作台。用户不用管理模型 token，就能在本地项目里使用多模型 Agent，并通过会话、产物和恢复入口承接长任务。
