# 全功能 UI 重构需求（未完成）

## 状态

未完成。本文先定义 UI 重构范围和信息架构，后续需要以 Hermes 为主参考，补充同类产品调研，再输出交互稿、视觉稿、组件规范和逐页验收。

## 背景

当前 UI 更像工程调试后台：侧栏包含 Chat、Prompts、DAGs、Tasks、Skills、Commands、Memory、Settings 等独立页面。产品落地需要主要参考 Hermes，并结合 Codex/Cursor 等同类产品，把账号、项目、会话、上下文、模型、产物和设置组织成一个连续体验。

DAG 由产品负责人另行设计，本需求只保留 DAG 的入口和信息架构接口，不深入 DAG 设计器。

## 目标

- 每个功能板块都重新设计，不只改主聊天页。
- 形成统一的产品信息架构和导航逻辑。
- 让新用户能从试用、登录、项目选择、发起任务、查看产物、管理用量完整走通。
- 保留现有工程能力，但隐藏低频调试入口，避免用户被内部模块名干扰。

## 重构范围

### 1. 登录与账号入口

- 登录页。
- 试用工作台入口。
- 账号菜单。
- 试用/充值/剩余用量入口。
- 个人账户页。

### 2. 主工作台

- 左侧：项目、会话、任务入口。
- 中间：聊天/Agent 执行主区域。
- 右侧：上下文、文件、产物、运行状态。
- 底部：输入框、模型选择、权限模式、附件和工具入口。

### 3. 项目与会话

- 项目选择。
- 会话列表。
- 会话归档/置顶/重命名。
- 会话恢复与继续。

### 4. 模型与用量

- 模型选择器。
- 可用/不可用模型状态。
- 剩余用量展示。
- 充值/升级入口。

### 5. 当前上下文与承接入口

- 主工作台右侧展示当前会话上下文来源。
- 已选文件/目录。
- Memory、Prompt、Skill、Shared Files 的生效状态。
- token 使用率和上下文风险。
- 会话恢复、继承会话、摘要/承接材料入口。
- 该区域只做主工作台内的上下文可视化和入口，不再单独拆上下文管理需求。

### 6. Memory / Prompt / Skills

- 从工程配置页改成产品化管理页。
- 用户能看懂“什么时候会生效”“对当前会话有什么影响”。
- 同名冲突、mirror drift 等高级能力保留，但放进高级处理流程。

### 7. Shared Files / 产物

- 产物列表。
- 最终产物标记。
- 从产物继续对话。
- 文件预览、复制、打开、删除。

### 8. 设置

- 账号设置。
- 模型/provider 设置。
- 权限/沙箱设置。
- 上下文阈值。
- 日志入口。

## 不做

- 不重写 DAG 设计器。
- 不在第一版做完整设计系统组件库。
- 不把所有内部调试页面暴露给普通用户。

## 信息架构建议

一级入口建议：

- 工作台
- 项目
- 产物
- 自动化/DAG 入口
- 账号与用量
- 设置

二级入口建议：

- 设置下放 Provider、权限、日志。
- Memory、Prompt、Skills 放入工作台右侧面板和设置高级区，不作为独立一级产品模块。
- 产物下放 Shared Files、Final Outputs。

## 页面级交付清单

### 登录页

- 支持账号登录，不使用“邮箱”作为前端主身份概念。
- 支持跳过登录进入试用工作台。
- 明确提示登录后可解锁更多模型、额度和功能。

### 试用工作台

- 默认进入主工作台结构，但权益处于试用态。
- 只允许选择基础模型。
- 高级模型在模型列表中可见但不可用。
- 账号入口显示登录动作，而不是账号详情。

### 主工作台

- 左侧展示项目、会话、任务入口。
- 中间展示对话、Agent 执行、工具调用和结果。
- 右侧展示当前上下文、文件、产物和运行状态。
- 底部展示输入框、模型选择器、附件、权限和工具入口。

### 模型选择器

- 展示模型名称、可用状态、消耗倍率和不可用原因。
- 未登录试用模型、已登录可用模型、未解锁模型要有明显区分。
- 未解锁模型点击后引导登录、充值或升级。

### 账号菜单

- 展示账号、剩余额度、套餐或试用状态。
- 展示充值入口、用量明细、设置和退出登录。
- 退出登录后立即回到试用态，并清空账号权益信息。

### 充值页

- 展示充值包或订阅档位。
- 展示支付状态。
- 支付成功后触发客户端权益刷新。
- 第一版可以先支持模拟支付或后台手动生效，但 UI 流程要完整。

### 产物页

- 展示会话产物、shared files、final outputs。
- 支持打开、预览、复制路径、删除。
- 支持从产物继续对话。

### 设置页

- 区分普通设置和高级设置。
- Provider、权限、日志、上下文阈值等高级配置默认不压迫主流程。

## 前端验收标准

- 用户登录后能直接进入工作台，而不是后台式页面集合。
- 未登录用户能进入试用工作台。
- 账号和剩余用量始终有稳定入口。
- 每个核心功能板块都有重新设计后的页面或面板。
- 普通用户不需要理解内部术语也能完成：新建任务、选择模型、添加上下文、查看结果、充值。
- 高级配置仍可访问，但默认不压迫主流程。
- 模型权限、账号权益、充值状态和会话恢复入口能在主流程中被发现。

## 后端/API 依赖

- 账号状态接口。
- 用量与权益接口。
- 当前上下文来源接口。
- 会话/项目/产物查询接口。
