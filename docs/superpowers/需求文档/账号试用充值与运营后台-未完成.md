# 账号试用充值与运营后台需求（未完成）

## 状态

未完成。本文先固化产品落地方向和技术边界，后续需要补充接口协议、后台页面字段和支付渠道方案。

## 背景

产品形态参考 Codex/Cursor 类桌面客户端：用户未登录时可以进入试用工作台，登录账号后解锁更多模型、额度和功能，并在本地工作台使用模型、Agent、上下文、文件和工具能力。商业闭环的本质是“卖别人的 token”：用户在本产品充值或订阅，本产品通过自有模型网关调度上游 token/API key，并按账号权益、余额和模型倍率扣费。

本需求统一使用“账号”，不使用“邮箱”作为产品概念。账号可以在技术实现中绑定手机号、邮箱、第三方登录或内部 ID，但前端展示和文案只说账号。

## 目标

- 未登录用户可以试用基础能力。
- 登录账号后解锁更多权限、更多模型和更高额度。
- 充值或订阅后解锁更多模型、更高额度和高级功能。
- 客户端可展示账号、剩余用量、可用模型、充值入口和退出登录。
- 模型请求必须经过服务端模型网关，由网关负责账号校验、模型路由、上游 token 调度、用量结算和失败归因。
- 支付后台支撑订单、支付回调、余额/套餐生效。
- 运营后台支撑账号查询、用量查询、上游 token 管理、模型倍率配置、手动调整、封禁/解封和基础统计。

## 范围

### 客户端

- 启动时检查登录态。
- 未登录可以进入试用工作台，但只能使用基础模型、基础额度和有限功能。
- 登录后进入完整工作台，并按账号权益展示更多模型、额度和功能。
- 账号菜单展示：账号名/账号 ID、剩余用量、可用模型、充值入口、个人账户、设置、退出登录。
- 模型选择器按账号权益显示可用/不可用模型。
- 未登录试用默认只开放基础模型和基础额度。
- 余额不足或模型未解锁时，阻止发起对应模型请求，并提示充值或升级。

### 账号与计费服务

- 账号登录与 session/token 校验。
- 账号权益查询：试用状态、余额、套餐、模型权限、功能开关。
- 用量扣减：按 token、turn、任务、模型倍率或内部计量规则扣减。
- 订单创建、支付回调、订单状态同步。
- 充值/订阅生效后更新账号权益。
- 用量流水记录：请求前预扣、请求后按实际上游 usage 结算、失败退款或释放预扣。

### 模型网关依赖

- 账号与充值链路依赖模型网关完成模型请求、权益校验、用量记录和失败回滚。
- 客户端不直接接触上游 token。
- 网关详细需求以《模型网关与计费路由需求》为准，本文不重复定义 token 池、模型路由和上游错误处理细节。

### 支付后台

- 订单列表、订单详情、支付状态、回调日志。
- 手动补单、退款标记、异常订单处理。
- 商品/套餐配置：试用额度、充值包、订阅档位、模型解锁规则。
- 模型倍率配置：不同模型对应不同消耗倍率。

### 运营后台

- 账号列表、账号详情、登录记录、设备记录。
- 用量流水、余额变化、模型调用统计。
- 上游 token/API key 列表、状态、剩余额度、错误率。
- 模型路由配置：模型启用状态、上游 provider、优先级、倍率。
- 手动增减额度、冻结账号、解冻账号。
- 基础数据看板：新增账号、活跃账号、充值金额、消耗量、失败率。

## 关键流程

### 登录启动

1. 客户端启动。
2. 检查本地 session token。
3. 调用账号状态接口。
4. 未登录或 token 失效：进入试用工作台，并提示登录可解锁更多权限。
5. 已登录：拉取权益和用量，进入完整工作台。

### 发起模型请求

1. 用户选择模型并发起任务。
2. 客户端检查本地权益缓存。
3. 客户端把请求发给模型网关，而不是直接发给上游 provider。
4. 网关校验账号、余额和模型权限。
5. 网关按模型路由选择可用上游 token/API key。
6. 网关向上游 provider 发起请求。
7. 网关根据实际上游 usage 和模型倍率结算用量。
8. 网关返回模型结果、用量和剩余额度。
9. 失败时返回明确原因：余额不足、模型未解锁、登录失效、上游 token 不可用、上游限流、服务异常。

### 充值生效

1. 用户在客户端点击充值。
2. 打开支付页或内嵌支付弹窗。
3. 服务端创建订单。
4. 支付渠道回调。
5. 后台更新订单和账号权益。
6. 客户端刷新剩余用量和可用模型。

## 初始接口草案

- `account/session/current`：返回当前账号、登录状态、账号展示名。
- `account/entitlements/get`：返回试用状态、余额、套餐、模型权限、功能开关。
- `gateway/chat/completions`：客户端模型请求入口，网关内部转发上游。
- `gateway/models/list`：返回当前账号可见模型、可用状态和倍率。
- `gateway/usage/estimate`：可选，请求前估算本次消耗。
- `billing/order/create`：创建充值或订阅订单。
- `billing/order/status`：查询订单状态。
- `usage/ledger/list`：查询账号用量流水。
- `admin/account/search`：运营后台账号搜索。
- `admin/account/adjust-quota`：运营后台手动调整额度。
- `admin/billing/orders`：支付后台订单列表。
- `admin/gateway/tokens`：运营后台管理上游 token/API key。
- `admin/gateway/routes`：运营后台管理模型路由、倍率和启用状态。

## 前端验收标准

- 未登录时可以进入试用工作台，但只能使用基础模型、基础额度和有限功能。
- 未登录状态下有明确登录入口，并提示登录可解锁更多模型、额度和功能。
- 登录后账号菜单能展示账号和剩余用量。
- 登录后可见更多模型和功能权限。
- 未登录试用只能选择基础模型。
- 未解锁模型在模型列表中可见但不可用，并提示充值/升级。
- 退出登录后立即回到试用工作台，并清除账号菜单中的账号权益信息。
- 充值成功后客户端能刷新用量和模型权限。
- 客户端模型请求不需要配置或暴露上游 token。

## 后端验收标准

- 所有核心模型请求都必须校验账号权益。
- 试用额度、充值额度、模型权限可配置。
- 用量扣减具备幂等保护，避免重复扣费。
- 支付回调可重复接收且不会重复生效。
- 模型网关必须隐藏上游 token，不向客户端返回真实 key。
- 模型网关必须记录上游 usage、倍率和最终扣费。
- 上游调用失败时，预扣额度必须释放或回滚。
- 运营后台可查询账号、订单、用量流水、模型路由和上游 token 状态。
