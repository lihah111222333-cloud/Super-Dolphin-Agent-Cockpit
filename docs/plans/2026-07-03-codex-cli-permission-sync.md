# Codex CLI Permission Sync Implementation Plan

> **For agentic workers:** 强制要求子技能: Use superpowers:子代理驱动开发 (recommended) or superpowers:执行计划 to implement this plan task-by-task. In super-agent-v3, subagents may use platform-native dispatch directly; use mcp-orch DAG runs and nodes (`task_create_dag` / `task_start_dag` / `task_dispatch_node` / `task_update_node`) only when persistent orchestration records are needed. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make saved Codex sandbox and approval settings affect newly created Codex threads and their first turns.

**Architecture:** The React settings page already persists provider preferences; the launch path must read those preferences in `resolveLaunchPreferences()` and include them in `thread/start`. Codex app-server 0.142.5 accepts legacy string `sandbox` on `thread/start`, while fine-grained writable roots/network settings belong to `turn/start.sandboxPolicy`, so the provider must store the canonical policy in session runtime config and attach it to each `turn/start`.

**Tech Stack:** React/Vite/Zustand frontend, Go provider adapter, Codex app-server JSON-RPC schema generated by `codex app-server generate-json-schema`, Vitest, guarded Go tests.

**Verification Surface:** `frontend-app/src/entities/client/model/useClientStore.js`, `frontend-app/src/pages/settings/SettingsPage.jsx`, `internal/module/thread`, `internal/provider/codexapp`, focused frontend tests, focused guarded Go tests, full frontend lint/test/build.

## Schema Fact To Preserve

Generated locally with:

```bash
codex --version
codex app-server generate-json-schema --out /tmp/codex-app-server-schema
```

Observed CLI version:

```text
codex-cli 0.142.5
```

Observed schema:

- `/tmp/codex-app-server-schema/v2/ThreadStartParams.json`: `sandbox` is `SandboxMode`, a string enum: `read-only`, `workspace-write`, `danger-full-access`.
- `/tmp/codex-app-server-schema/v2/TurnStartParams.json`: `sandboxPolicy` is a `SandboxPolicy` object. `workspaceWrite` supports `writableRoots` and `networkAccess`.

Implementation must therefore keep `thread/start.sandbox` as a legacy mode string and add `turn/start.sandboxPolicy` for fine-grained settings.

- [ ] **Step 5: Implement sandbox conversion helpers**

In `internal/provider/codexapp/driver.go`, keep `codexSandboxWireJSON()` returning only the legacy mode string for `thread/start`.

Add:

```go
func codexSandboxPolicyWireJSON(raw json.RawMessage) json.RawMessage {
	raw = json.RawMessage(strings.TrimSpace(string(raw)))
	if len(raw) == 0 {
		return nil
	}
	var text string
	if err := json.Unmarshal(raw, &text); err == nil {
		return codexSandboxPolicyFromMode(text)
	}
	var obj map[string]any
	if err := json.Unmarshal(raw, &obj); err != nil {
		return raw
	}
	mode := sandboxModeObjectValue(obj)
	switch mode {
	case "workspace-write":
		out := map[string]any{"type": "workspaceWrite"}
		if roots, ok := obj["writableRoots"]; ok {
			out["writableRoots"] = roots
		}
		if roots, ok := obj["writable_roots"]; ok {
			out["writableRoots"] = roots
		}
		if network, ok := obj["networkAccess"]; ok {
			out["networkAccess"] = network
		}
		if network, ok := obj["network_access"]; ok {
			out["networkAccess"] = network
		}
		return mustJSON(out)
	case "read-only":
		out := map[string]any{"type": "readOnly"}
		if network, ok := obj["networkAccess"]; ok {
			out["networkAccess"] = network
		}
		return mustJSON(out)
	case "danger-full-access":
		return mustJSON(map[string]any{"type": "dangerFullAccess"})
	default:
		return raw
	}
}

func codexSandboxPolicyFromMode(mode string) json.RawMessage {
	switch canonicalCodexSandboxMode(mode) {
	case "workspace-write":
		return mustJSON(map[string]any{"type": "workspaceWrite"})
	case "read-only":
		return mustJSON(map[string]any{"type": "readOnly"})
	case "danger-full-access":
		return mustJSON(map[string]any{"type": "dangerFullAccess"})
	default:
		return nil
	}
}
```
