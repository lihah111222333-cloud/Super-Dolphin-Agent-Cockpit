# M5 复审裁决

## 多机意见汇总

| 议题 | 机器意见 | 裁决 |
| --- | --- | --- |
| 是否全量统一列表出参 | A 倾向全量统一，B/C 认为数组型工具风险高 | 不全量强改，先做对象型工具 |
| 是否保留旧字段 | 三台机器一致要求保留 | 保留 `dags/runs/files/providers` |
| 是否新增统一字段 | 三台机器一致支持 | 新增 `data/total/showing/truncated/hint` |
| 是否要 hint | 三台机器一致认为能降低 AI 认知负担 | 每个已处理列表工具必须给下一步 hint |
| 数组型工具怎么处理 | A 建议直接迁移，B/C 建议单独阶段 | 进入缺口表，下一轮设计兼容模式 |

## 最终裁决

M5 只做低风险、可回滚、兼容式优化：

1. 对对象型列表工具新增统一 envelope 字段。
2. 保留旧字段，保证现有客户端不受影响。
3. 不修改直接数组型工具的 wire shape。
4. 把直接数组型工具登记为剩余缺口，进入下一轮反馈循环。

这个裁决符合领导要求的“补剩余缺口，形成反馈闭环”：不是跳过问题，而是把高风险问题独立入账，避免为追求表面统一制造线上兼容事故。
