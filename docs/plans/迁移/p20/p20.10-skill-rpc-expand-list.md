### 5.1 Host RPC schema 定稿（审查补记）
- `skill/list` request：`{}`
  - v1 不加 query/filter，避免 strict decode 下反复扩字段。
- `skill/list` response：
  - `{"skills":[{"name","summary","description","trust","content_hash","disable_model_invocation"}]}`
  - **不要**直接复用 `SkillInfo` 全量 JSON；`dir` / `trigger_words` / `force_words` / `allowed_tools` 不进 v1 list，避免泄露绝对路径与编辑器侧元数据。
- `skill/expand` request：
  - `{"name":"go-testing","section":"## Usage"|"references/api.md","max_bytes":20000}`
  - `section == ""` 或以 `#` 开头：读取 `SKILL.md` 全文或 H2/H3 子段；否则按 skill dir 内相对路径读取资源文件。
  - v1 **不要求** hash / ETag / version 请求参数；服务端始终返回最新内容与 `content_hash`。若后续需要客户端去重，再向后兼容新增 `if_hash`。
- `skill/expand` response：
  - `{"name","section","path","summary","content","truncated","total_bytes","content_hash","trust"}`
  - `content_hash` 取“选中 section / 资源内容在截断前”的 SHA-256；这样同一 section 仅 `max_bytes` 变化时 hash 仍稳定。
  - `path` 属于 host 诊断字段；后续 `p20.11` 的 MCP adapter 可按需要裁掉。

### 5.2 错误语义与命名边界（审查补记）
- **host RPC** 走 JSON-RPC error path，不在 result 里塞 `is_error`；`is_error` 是 MCP tool/result 层语义，见 `internal/provider/claudecli/factory.go:171-193`。
- 建议错误语义：
  - 非法 `name/section/max_bytes`、path escape → `-32602`（invalid params）
  - skill not found → `-31001`（复用 `rpc.ErrNotFound`）
  - approval required / denied → 如本单要覆盖审批握手，新增 host helper；**不要**复用 `-31005`（它语义是 timeout）
- 结论：`-32001 ~ -32099` 不在本单 host RPC 先行引入；若 `p20.11` MCP adapter 需要保留 JSON-RPC server-error 带，再在 tool 层单独预留。

### 5.3 共存 / 替换结论（审查补记）
- `skills/list` / `skills/local/*` / `skills/match/preview` 继续保留：它们属于编辑器 / UI / preview surface。
- 新 `skill/list` / `skill/expand` 是 **name-based + read-only + progressive-disclosure** surface。
- host RPC 继续用 slash：`skill/list`、`skill/expand`；MCP tool 继续用 underscore：`skill_list`、`skill_expand`，参考 `internal/sidecar/orch/tools/prompt_tools.go:50-60` 的 `prompt_list` / `prompt_get`。
