# Bug #2 / 断点 B：per-turn skill 由“仅 Name”补齐为可注入实体

> 创建时间：2026-04-19 | 状态：📝 已补锚点 / 可派单 | 依赖：独立（critical-path 首段）
> Agent 预算：1 个 codex agent，改动 ≤6 文件，≤450 行/文件

## 1. 目标（1-3 句）
修掉手动/强制 skill 在 turn 运行时被降成 `SkillRef{Name}` 的断链。目标是让 provider 在收到 turn request 时，至少能拿到非空 `Prompt` 或已定型的 `Summary/Mode` 语义，而不是被 `skill.Prompt==""` 直接跳过。

## 2. 前置依赖
- 独立（critical-path 首段）
- 本单只负责自己的 write set；跨 provider / 跨前后端联动留给显式依赖单处理。

## 3. 源码锚点（复用 `source-refs-appendix.md`）
- [SRC-A01](source-refs-appendix.md#src-a01) — DTO 已具备 `Version/Mode/Summary/Source` 字段
- [SRC-B04](source-refs-appendix.md#src-b04) — name-only 入口 `normalizeSkillNames()`
- [SRC-B05](source-refs-appendix.md#src-b05) — `PrepareTurn()` 当前未补全文实体
- [SRC-B06](source-refs-appendix.md#src-b06) — codex provider 空 prompt 直接跳过

## 7. 风险与回退
- **高风险：把 I/O 放进 factory/resolver**。`normalizeSkillNames()` / `Resolve()` 当前是纯函数；若把 `ListSkills/ReadLocal` 直接塞进去，会把测试和调用链放大。I/O 应只放在 `PrepareTurn()` 前置 hydrate 步。
- **高风险：`ReadLocal()` 返回 `any`**。turn 侧解包必须做严格 map/type 断言，不能裸转导致 panic。
- **中风险：误把本单做成 resolver 矩阵**。`CandidateSkills` 生产路径当前并未接通；矩阵、top-k、TTL 一律留给 `p20.8`。
- 回退：只回滚 turn hydration 与 codex fallback；不要触碰 `thread/start` 契约与 launch path，那是 `p20.3/p20.4` 范围。
