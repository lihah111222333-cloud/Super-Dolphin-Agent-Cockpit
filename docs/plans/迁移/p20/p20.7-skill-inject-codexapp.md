## 2. 前置依赖 / 合入 gate
- p20.4：launch assembly 已能承载 launch-time skill manifest。
- 与 `p20.6` 必须共享 `internal/contract/skill_injection.go`，method set 必须逐字对齐；`dto.TurnRequest` / `dto.SteerRequest` 的 `SkillPrompt` carrier 与 provider-name registry 也必须同步复用。
- 合入 gate：`p20.9` 读端先发；若未先发，本单必须保留 legacy `[skill:name] + 摘要:/使用方式:` 兼容写法，不能单独切新 marker。
- 本单只负责 codex provider + shared contract；不顺手改 prompt/skill/前端。

## 4. 共享 Port 契约（与 p20.6 对齐）
- 共享合同文件：`internal/contract/skill_injection.go`
- 审查建议 method set（按当前 provider 实际落点收敛）：

```go
type SkillInjectionPort interface {
    InjectL1Manifest(baseInstructions, manifest string) string
    BuildTurnSection(refs []dto.SkillRef) (string, bool)
    ReservedTokens() int
}
```

- 结论：
  1. contract 不能返回 `turnInputItem` / Claude stream block 之类 provider-specific 类型。
  2. 与 `p20.6` 一致：module 层经 provider-name registry 调 `BuildTurnSection()`，结果写入 `req.SkillPrompt`；codex `session_turn.go` 只负责把 carrier 包成 `turnInputItem`。
  3. `InjectL1Manifest()` 必须由 `startAssemblyInstructions()` 统一调用，保证 runtime config snapshot 与 `thread/start` RPC params 一致。
  4. `ReservedTokens()` 只给上层预算 / 日志，不参与 provider 互相调用。

## 8. 实施步骤（编号 1-N）
1. 先在 `internal/contract/skill_injection.go` 固化共享 method set，并与 `p20.6` 逐字对齐。
2. 在 `internal/provider/codexapp/skill_inject.go` 实现 codex port：Full 注全文、Summary 注摘要指针、None 跳过。
3. 在 `internal/provider/unified/registry.go` / `internal/module/turn/service.go` 打通 provider-name resolve，把 `BuildTurnSection()` 结果统一写入 `req.SkillPrompt`。
4. 让 `driver.go:startAssemblyInstructions()` 统一追加 L1 manifest；`StartSession()` 与 `buildThreadStartParams()` 共享同一合并结果。
5. `session_turn.go` 只负责消费 `req.SkillPrompt` 并包装成 `turnInputItem`，不再直接读取 `skill.Prompt`；若沿用 `turnInputsFromRequest()` helper，则签名改为 `(inputs, skills, assembly, skillPrompt string)` 并同步更新 `buildTurnStartParams()` / `buildTurnSteerParams()` 两个 caller；或在这两个入口先把 `SkillPrompt` 预包成 input 再复用剩余 mapping。
6. 补测试；若 `p20.9` 未先落，测试必须断言 legacy 兼容写法仍可被现有 rollout trim 清掉。

## 10. 风险与回退
- 风险 1：只改 `buildThreadStartParams()` 不改 `StartSession()`，会导致 runtime config 与 remote `thread/start` 不一致。
- 风险 2：若 codex 继续 provider-local 拼接 skill 文本，会与 `p20.6` 的 module-registry 方案分叉。
- 风险 3：新 marker 先发、读端未切，会把 skill block 当用户输入回放。
- 回退：保留 legacy 写法；共享 contract + carrier/registry 先落一个最小 commit，再分 provider 实现。
