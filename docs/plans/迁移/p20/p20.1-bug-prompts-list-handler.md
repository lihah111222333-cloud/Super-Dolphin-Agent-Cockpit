### 4.2 当前真实签名 + 预期签名变化
- `internal/store/prompt/contract.go`
  - 当前：`type Reader interface { List(ctx context.Context, filter ListFilter) ([]PromptTemplate, error) }`
  - 预期：`Reader` **不改签名**；新增 `type Store interface { Reader; WithTx(ctx context.Context, fn func(txStore Store) error) error; Get(ctx context.Context, promptKey string) (*PromptTemplate, error); Delete(ctx context.Context, promptKey string) error; InsertVersion(ctx context.Context, version PromptTemplateVersion) error; Upsert(ctx context.Context, template PromptTemplate) (*PromptTemplate, error) }`
  - 影响：`dashboard` 仍依赖 `Reader`；`prompts/list|write|delete` handler 依赖 `Store`
- `internal/store/prompt/store.go`
  - 当前：`func NewStore(q *sqlc.Queries) Reader`
  - 预期：`func NewStore(q *sqlc.Queries) Store`
  - 影响：`internal/store/prompt/module.go` 必须同改 `Reader` adapter；否则 `dashboard.service` 的 `Prompts promptstore.Reader` 注入会断
- `internal/module/prompt`
  - 当前：无宿主 prompt handler provider
  - 预期：在 `service.go` / `module.go` **现有文件**内新增 `registerPromptHandlers(store promptstore.Store) rpc.HandlerMapResult`（命名可等价），并由 `module.go` `fx.Provide(...)` 注册
  - 影响：运行时经 `rpc.Server.Register()` 生效；**禁止**新建 `internal/module/prompt/rpc.go`

## 7. 风险与回退
- **高风险：fx 类型注入**。若把 `NewStore` 改成返回 `Store` 却忘了补 `Reader` adapter，`dashboard` 会在 fx 装配期直接断掉。
- **高风险：丢掉 scope/tag 规则**。`c50ef009^` 删除前的 `prompt_service.go` 里有 `scope.cwd:` tag 规则；若只恢复 CRUD 不恢复 scope，会造成跨项目 prompt 泄漏。
- **中风险：response DTO 漂移**。前端吃的是 `id/name/content/description/agentType/createdAt`；若直接透传 store DTO，会导致页面“有 handler 但仍显示空卡片”。
- 回退：仅回滚 prompt handler 注册与 store 写接口；不要动 `dashboard/prompts` 和其它 prompt assembly provider。
