# skill scope 导入选项 + 对齐上游 agent 存储约定

> 创建时间：2026-04-20 | 状态：📝 可派单 | 依赖：p20.10（skill/list + skill/expand）+ p20.13（approval）+ p20.17（cwd 参数化已合入）
> Agent 预算：1 个 codex agent 串行实施，改动 ≤14 文件，≤450 行/文件

---

## 1. 目标（1-3 句）

让用户在 UI 导入/保存 skill 时能选择 **项目 scope**（与当前 cwd 绑定）或 **系统 scope**（跨 cwd 全局共享），并把系统 scope 的存储布局**对齐上游 claude / codex CLI 的 skill 约定**（无 project-key 隔离）。Launch picker + skill editor 双入口都要支持此切换，后端 scanSkills 同时识别两种布局。

## 2. 现状诊断

### 2.1 当前存储布局（p20.17 后）

| 来源 | 路径 | trust |
|---|---|---|
| 项目本地 | `<cwd>/.agent/skills/<skill>/SKILL.md` | `project` |
| 系统 per-project | `~/.super-dolphin/skills/<project-key>/by-id/<skill>/SKILL.md` | `user` |
| 系统全局 | ❌ **当前没有此路径约定** | - |

### 2.2 上游 agent 习惯

- **claude CLI**：`~/.claude/skills/<skill>/SKILL.md`（**全局共享，无 project-key**）；项目级 `<cwd>/.claude/skills/<skill>/SKILL.md`
- **codex CLI**：类似 `~/.codex/skills/`（近期设计）
- **统一语义**：**系统级无 project-key 隔离**，跨所有 cwd 共享

### 2.3 错位

p20.17 把系统 root 也强制用 `<project-key>/by-id/*` 隔离，与"系统级共享"的习惯**不一致**。用户在 cwd=A 写的"系统技能"实际只被 cwd=A 看到，违背直觉。

### 2.4 前端入口现状

- `cmd/agent-terminal/frontend/vue-app/composables/useSkillEditor.js:138` 用 `skills/local/importDir` 导入目录
- `cmd/agent-terminal/frontend/vue-app/composables/useSkillEditor.js:275` 用 `skills/local/write` 保存单文件
- 两个入口都**无 scope 参数**（默认落项目路径 `<cwd>/.agent/skills/`）
- `LaunchSkillPicker` 展示从 `skills/list` 拿到的混合列表，**无 scope 分组 UI**

### 2.5 trust 字段已有基础

`skillListItem.Trust` 枚举（`user | project | signed`）已由 `scanSkills` 按 root 推断后暴露到 skills/list response，前端可直接消费；只需补"系统共享"和"项目共享"两层路径再加 scanner gate。

## 3. 决策矩阵

### 3.1 存储布局定稿

| Scope | 路径 | trust | 扫描 gate |
|---|---|---|---|
| **project** | `<cwd>/.agent/skills/<skill>/SKILL.md` | `project` | 所有 cwd（scanSkills 永远扫 cwd 下这条）|
| **system-global**（**新**） | `~/.super-dolphin/skills/<skill>/SKILL.md`（**无 project-key 层**）| `user` | 所有 cwd 共享，scanSkills 任意 cwd 都扫 |
| **system-per-project**（p20.17 遗留） | `~/.super-dolphin/skills/<project-key>/by-id/<skill>/SKILL.md` | `user` | 仅当 project-key 匹配当前 cwd 时扫 |

**新建时默认只用前两种（project / system-global）**；p20.17 per-project 布局作为**读兼容**保留，不再新建。

### 3.2 UI 入口

| 入口 | 动作 | scope 选择方式 |
|---|---|---|
| `LaunchSkillPicker` | 展示+选中 launch skill | **scope tab**（project / system）切换列表；多选跨 scope 合并 |
| `useSkillEditor` 新建/保存 | `skills/local/write` | **scope radio**（在 form 里）：project（默认）/ system |
| `useSkillEditor` 导入目录 | `skills/local/importDir` | **scope radio**（在弹窗里） |

### 3.3 RPC 契约变更（additive）

| RPC | 新增参数 | 语义 |
|---|---|---|
| `skills/local/write` | `scope: "project" \| "system"` (optional, default `"project"`) | 决定 target path 前缀 |
| `skills/local/importDir` | 同上 | 同上 |
| `skills/list` | 无需改 | response.trust 已可区分 |
| `skills/delete` | 无需改（按 name + cwd 解析已有 skill 位置） | 删对应位置 |

## 9. 风险与回退

| 风险 | 缓解 |
|---|---|
| `~/.super-dolphin/skills/<skill>/` 新布局与 p20.17 `<project-key>/by-id/` 新旧混存 | union 扫描；写端默认新布局，读端同时兼容 |
