# L1 Catalog：把 skill 静态清单接入 prompt DynamicSection

> 创建时间：2026-04-19 | 状态：✅ **已由 P20.1 Phase 8-10 完成**（`c1ead48`→`00b073f`） | 依赖：p20.4 ✅
> 审查日期：2026-04-19 | 结论：改落点，保 contract / slot，不把 `skillSvc` 硬塞进 `prompt.NewService()`
> ⏹ **关单备注**：SkillCatalogProvider 安全投影 + 4 分组 + 元指令 + fx 灰度 + 5 counter 已全部落在 `internal/module/prompt/skill_catalog_provider.go` + `skill_catalog_fx.go` + `pkg/skillmetrics/`。落点从原计划的 `skill` 包改到 `prompt` 包（freeze 已放行）。

## 1. 目标（1-3 句）
把现有 `scanSkills()/ListSkills()` 产出的静态元数据接入启动期 prompt，形成 L1 Core / Index catalog。此单只负责 L1 manifest 与 dynamic slot，不负责 per-turn 注入与 `skill_expand`。

## 2. 审查结论（先看这个）
- 现有元数据来源成立：`internal/module/skill/skills_meta.go:22-45` 的 `scanSkills()` + `internal/module/skill/skills_fs.go:17-27` 的 `ListSkills()` 已足够支撑 L1 catalog。
- **当前文档落点不合规**：不应把 `skill.Service` 直接注入 `internal/module/prompt/service.go:47-72` 的 `NewService()`。仓库里外部 dynamic provider 的既有模式是 `contract.DynamicSectionRegistrar` + owning module `fx.Invoke` 注册（见 `internal/module/memory/module.go:218-245`、`rules_provider.go:465-488`）。
- **当前文档文件落点也不合规**：`internal/module/prompt` 目前 non-test/non-factory 文件数已在 freeze 上限 `26/26`（`internal/archtest/freeze_registry.go:19-35`，本地 2026-04-19 核查）。若再新建 `internal/module/prompt/skill_catalog_provider.go`，`TestCodeSizeGuard` 会直接炸。**修订后 provider 应落在 `internal/module/skill/`，prompt 侧只增 slot/contract。**
- `CacheByName` 可以保留，但必须补 **明确失效策略**：`write/delete/import/summary` 变更后经 `publishSkillsChanged()` 触发 `SectionInvalidator.InvalidateSections(..., DynamicSectionSkillCatalog)`；否则新 session 也会继续读到旧 catalog。

## 4. 修订后的代码落点

### 4.2 改动文件（file:line + 改点）
- `internal/contract/prompt.go:89-105,193-208` — 在**现有文件**内新增 `DynamicSectionSkillCatalog` slot key 常量；复用 `DynamicSectionProvider` / `DynamicSectionRegistrar`

### 4.3 `CacheByName` 失效策略（必须写清）
1. `skill write/import/delete` 成功后，skill 模块 owning service 负责触发 `publishSkillsChanged()`。
2. `publishSkillsChanged()` 的订阅侧调用 `SectionInvalidator.InvalidateSections(..., DynamicSectionSkillCatalog)`，只失效 `skill_catalog`，不整包清空 prompt cache。
3. `summary/description` 更新也必须走同一失效链；否则 catalog 会出现“正文已变、L1 仍旧”的陈旧窗口。
4. 若首版失效链来不及合入，临时回退只能是把 slot 降为 `Uncached`；不能保留 `CacheByName` 却不做 invalidation。

## 5. 实施步骤（修订后）
1. 在 `internal/contract/prompt.go` / `internal/module/prompt/dynamic.go` 的**现有文件**内补 `skill_catalog` slot，并明确 `startOnly + CacheByName`。
2. 在 `internal/module/skill/skill_catalog_provider.go` 实现 provider，直接消费 `ListSkills()`，按 Core / Index 两级渲染。
3. 在 `internal/module/skill/module.go` 通过 `contract.DynamicSectionRegistrar` + skill 包 `fx.Invoke` 反向注册 provider，不改 `prompt.NewService()` 构造签名。
4. 在 skill 写/删/导入/summary 变更链路补 prompt section 失效，保证 `CacheByName` 不陈旧。
5. 测试 Core / Index、排序、budget 截断、空列表、失效后重建；默认并入 `internal/module/skill/skills_meta_test.go`，仅当实施时 `internal/module/skill` package-count 仍 `<25` 且单文件/函数预算受压，才允许拆出 `skill_catalog_provider_test.go`；同时跑 archtest，确认 prompt 包 freeze 不回退。

## 6. 验收标准
- 功能：新 session 的 start assembly 能渲染 `skill_catalog`；turn assembly 不泄漏该 section（`startOnly=true` 生效）
- 分层：`prompt` 模块不直接依赖 `internal/module/skill`；注册通过 `contract.DynamicSectionRegistrar`
- 守卫：`go test ./internal/module/skill/... ./internal/module/prompt/...` 绿；catalog 断言优先落在 `internal/module/skill/skills_meta_test.go`（如预算允许才拆 `skill_catalog_provider_test.go`）；`go test ./internal/archtest -run 'TestCodeSizeGuard|TestFreezeRegistryIntegrity|TestDependencyDirection'` 绿
- 兼容：skill 为空时返回空 section；50+ skills 时按 budget 截断，不 panic

## 7. 风险与回退
- 风险 1：若继续把 provider 放进 `internal/module/prompt/`，会命中 freeze registry；**回退策略：立即改回 skill 模块 owning-provider 落点**。
- 风险 2：若 `CacheByName` 没有失效钩子，skill 更新后 catalog 会长期陈旧；**回退策略：先降为 `Uncached`，待失效链补齐后再切回 `CacheByName`**。
- 风险 3：若把 `Expand/GetSummary/ReadBody` 混进本单，会把 L1 和 Phase 6 绑定，扩大写集；**回退策略：严格只做 `ListSkills()` 元数据消费**。

## 8. 合规结论
- **prompt 侧**：✅ 只在 `prompt.go` / `dynamic.go` 既有文件内补 slot key 与 spec，**0 新增 prod 文件**，不再冲击 prompt freeze。
- **skill 侧**：⚠️ 按本轮审查口径新增 `skill_catalog_provider.go` 后为 `24→25`，压线；因此 catalog 测试默认并入 `internal/module/skill/skills_meta_test.go`，仅当实施时 `internal/module/skill` package-count 仍 `<25` 且单文件/函数预算受压，才允许再拆 `skill_catalog_provider_test.go`。
- **分层**：✅ 注册路径固定为 `contract.DynamicSectionRegistrar` + skill 包 `fx.Invoke` 反向注册；`prompt.NewService()` 保持不注入 `skill.Service`。
- **失效策略**：✅ `CacheByName` 只有在 `SectionInvalidator` 链接通时才成立；否则应显式降级为 `Uncached`。
