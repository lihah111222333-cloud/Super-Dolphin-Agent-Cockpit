## 5. 实施步骤（编号 1-N）
1. 前端 `startThread()` 接受 `options.selectedSkills` / `options.manualSkillSelection`，launch 时仅做透传，不做解析。
2. `thread/start` public RPC 入口保留 `selectedSkills/manualSkillSelection` 名称，但在 `newStartHandler()` 内投影成 `LaunchSkillNames/ForceLaunchSkills`。
3. 仅扩展 `thread.StartRequest` 与 `dto.StartSessionRequest`；保持空值兼容：`nil/false` 不改变旧行为，codex provider wire 继续维持现状并交给 `p20.7` 在 `BaseInstructions` 单点注入。
4. 补 `rpc_types_test.go`、`start_session_guard_test.go` 与前端 round-trip 测试，证明新字段 snake/camel 兼容、DTO 透传不丢。

## 6. 验收标准

## 7. critical-path 闭环检查
- **p20.2 -> p20.3**：`p20.2` 产出的是 turn 侧 hydrated `dto.SkillRef`；`p20.3` 只运输 launch 名称，不直接消费 `SkillRef` 实体。这个依赖是“语义对齐”而非“类型复用”。
- **当前不对齐点**：`cmd/agent-terminal/frontend/vue-app/composables/useThreadActions.js:103-125` 仍是“先 `startThread()`，后 `resolveComposerSkillSelectionForSend()`”；因此 **首条聊天消息路径拿不到 launch skills**。该缺口需由 `p20.14`（LaunchSkillPicker）或后续 sequencing 调整补齐，不应在本单内顺手扩大 write set。
- **p20.3 -> p20.4 / p20.7**：本单必须把 `LaunchSkillNames/ForceLaunchSkills` 放进 `StartRequest` / `StartSessionRequest`，这样 `p20.4` 才能把它们送进 `StartInput / StartAssembly / Snapshot`，`p20.7` 才能把 manifest 并入 codex `BaseInstructions`；本单不再创建 provider-side 平行 wire。

## 8. 风险与回退
- 风险：如果在本单直接改 StartAssembly 或另开 `threadStartParams` skill 字段，会把 transport 与 assembly/provider 注入耦合，重新制造 split-brain。
- 回退：字段保持 optional；若后续 `p20.4` / `p20.7` 暂未合入，旧 provider 行为保持不变。

## 合规结论
- **仓库契约**：本单应保持 core package **0 新文件**。当前生产文件计数（排除 `_test.go`）为：`internal/module/thread=25`、`internal/dto/provider=9`、`internal/provider/codexapp=18`。其中 `thread` 已卡在默认包文件预算 25；因此只允许改现有 thread 测试文件，`codexapp` 在本单只作 read-only 锚点。
- **分层合规**：public RPC 兼容层放 `internal/module/thread/rpc_types.go`；跨 layer DTO 放 `internal/dto/provider/session.go`；launch 生命周期编排留在 `internal/module/thread/*`；provider-specific manifest 注入显式交给 `p20.7`。无 `provider -> module/prompt` 反向依赖。
- **DTO 破坏性变更评估**：本单为 additive optional 字段；`startParams` 通过 camel/snake 双读保持 V2 兼容；`dto.StartSessionRequest` 为内部共享 DTO，旧 caller 不写新字段时行为不变；这些字段保留给 snapshot/resume 与 `p20.7` 消费，**rollout snapshot 尚未触碰**。
- **fx wiring 变更清单**：无。`prompt.Module`、`thread.Module`、provider modules 均不需改 DI。
- **freeze registry 预估调整**：无；若误新建 `internal/module/thread/*_test.go`，`thread` 包文件数会从 `25 -> 26`，立刻触发预算违规。
- **循环依赖 sanity check**：无新增环。新增字段只沿 `frontend -> thread RPC -> thread service -> dto/provider` 单向流动，provider 端消费留给后续单点注入。
- **测试入口锚定**：`thread-store.actions.test.js`、`rpc_types_test.go`、`start_session_guard_test.go` 是最小必改；`./internal/provider/unified/...` 为共享 DTO 回归锚点。
