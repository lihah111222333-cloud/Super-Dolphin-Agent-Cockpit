# 前端：为 Launch 新增 Skill Picker，并复用 `selectedSkills` 传输链

> 创建时间：2026-04-19 | 状态：⚠️ 审查后待补依赖 | 依赖：p20.3（launch-time skill contract） + feature source `features.launchSkillSelection`
> Agent 预算：1 个 codex agent，改动 ≤9 文件；`thread-actions-helpers.js` 当前 613 行，新增逻辑必须极小或拆出 helper

## 1. 目标（1-3 句）
在 thread 尚未创建前也能做 skill 选择，并把选择结果通过 `thread/start` 带入 launch。实现时必须复用现有 `selectedSkills` / `manualSkillSelection` 语义，避免发明第二套状态模型。

## 2. 审查结论（基于 2026-04-19 LSP）
- 现有技能选择 UI 完整落在 `cmd/agent-terminal/frontend/vue-app/components/ComposerBar.js:281-313`；如果 launch 再画一套而不收口，用户会在“未建线程”场景看到**双份 skill selector**。
- 现有 force-match / manual-merge 语义已经固化在 `useSkillPreview.js:45-56,181-205`：`selectedSkills = manual + forceMatched`，`manualSkillSelection` 只看手工选择。Launch 侧应直接复用这套 shape。
- `performSend()` 当前顺序是：`startThread()` → `resolveComposerSkillSelectionForSend()` → `sendMessage()`（`useThreadActions.js:103-125`）。这意味着 launch path **来不及把选中的 skills 带进 `thread/start`**。
- `thread-actions-helpers.js:288-297` 的 `startThread()` 目前只发 `{cwd, modelProvider}`；后端 `thread/start` 合同也没有 skill 字段（`internal/module/thread/rpc_types.go:26-45`、`internal/module/thread/contract.go:35-63`、`internal/dto/provider/session.go:55-63`、`internal/provider/codexapp/driver.go:64-76`）。所以本单**不是独立前端单**，至少依赖 p20.3 把 launch-time skill 载荷打通。
- 仓库内目前**没有任何** `features.launchSkillSelection` 命中（前端/后端均为 0 命中）；本单只能“消费可选 feature source 并在缺失时隐藏”，不能假设 gate 已存在。
- `thread-actions-helpers.js` 已有 613 行，超过前端单文件 600 行约束；若继续堆逻辑，架构上不合规。该文件的改动应控制在“start payload 附带字段”的极小 diff，选择/预览逻辑必须外移到新增 `services/*` / `composables/*`。

## 3. 前置依赖
- 依赖 p20.3：`thread/start` 需要先具备 `selectedSkills` / `manualSkillSelection` 载荷能力；否则 LaunchSkillPicker 只能停留在 UI 层，无法真正影响 launch。
- `features.launchSkillSelection` 需要由别的单提供；本单只消费可选字段，**缺失时不显示**，不在这里发明新配置入口。
- `useSkillPreview` 的现有 composer 逻辑保留不动；Launch 侧通过新 composable 复用 `utils/skill-match-utils.js` 的 merge/dedupe 规则，避免和 composer 彼此写穿。

## 6. 组件边界 / 对齐策略
- `LaunchSkillPicker.js`：**纯展示层**。输入为 `skills`、`matches`、`selectedSkillNames`、`loading`、`enabled`；输出仅 `toggle-skill / select-all / clear / refresh`。
- `useLaunchSkillSelection.js`：**状态层**。负责：
  - 通过 `services/skills-api.js` 读取 `skills/list`
  - 通过 `skills/match/preview`（`threadId=''`）计算 launch-time matches
  - 复用 `utils/skill-match-utils.js` 的 `mergeSkillNameLists()` / `collectForceMatchedSkillNames()`
  - 产出与 composer send-path 完全一致的 `{ selectedSkills, manualSkillSelection }`
- `services/skills-api.js`：**唯一 RPC 入口**。Launch 相关的 skill API 不在组件/页面里直接写 `callAPI()`，避免绕开现有 `services/*` 组织方式。
- `ComposerBar.js`：继续只负责“已有 thread 的 composer”；不要把 launch state 混进 composer store。

## 7. `performSend()` 顺序改造
1. 若已有 `selectedThreadId`：保持现有路径，继续走 `resolveComposerSkillSelectionForSend(threadId, text)`。
2. 若 `selectedThreadId` 为空：
   - 先从 `useLaunchSkillSelection()` 读取 launch state，拿到 `{ selectedSkills, manualSkillSelection }`
   - 再调用 `threadStore.startThread(cwd, { focusMode, selectedSkills, manualSkillSelection })`
   - 线程创建成功后照常 `threadStore.sendMessage(...)`
3. Launch-only state 在 `startThread` 成功后清空；若 `startThread` 失败则保留，避免用户重新勾选。
4. 不要在 blank-thread 首发路径里重复调用 composer 的 `resolveComposerSkillSelectionForSend()`；否则会把 launch state 与 composer state 混成两套来源。

## 8. 实施步骤（编号 1-N）
1. 新增 `services/skills-api.js`，把 launch picker 用到的 skill RPC 收口到 service 层。
2. 新增 `useLaunchSkillSelection.js`，内部消费可选 `features.launchSkillSelection`；缺失时返回 disabled 空状态。
3. 新增 `LaunchSkillPicker.js`，只接 UI props / emits，不触碰 thread store / callAPI。
4. `UnifiedChatPage` 接入 launch composable，并在 template 中只对“无当前线程 + feature gate 开启”渲染 launch picker。
5. `ComposerBar.js` 在 `threadId` 为空时隐藏现 selector，避免双显。
6. `useThreadActions.js` 改 `performSend()` 顺序；`thread-actions-helpers.js` 只补极小的 `thread/start` 发包字段。
7. 补行为测试：优先落 `composer-bar.behavior.test.js` 与 `use-thread-actions.test.js`；必要时再独立新增 `launch-skill-picker.behavior.test.js`。

## 9. 验收标准
- `LaunchSkillPicker` 不直连 `callAPI()`；所有 RPC 经 `services/skills-api.js` → `services/api.js`。
- `features.launchSkillSelection` 缺失时，launch picker 完全不显示，旧行为不变。
- blank-thread 首发路径下，`performSend()` 会先解析 launch skill state，再调用 `threadStore.startThread()`。
- `threadStore.startThread()` 最终会把 `selectedSkills/manualSkillSelection` 带入 `thread/start`（以前端合同为准，等待 p20.3 落地后真正生效）。
