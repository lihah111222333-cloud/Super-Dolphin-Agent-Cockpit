### 4.3 审查补充 / 架构合规结论
- authoritative 契约仍然是 `prompts/list|write|delete` host RPC（见 `p20.1`）；fallback 只能兜底 Bug #1，不能把 `dashboard/prompts` 变成新的主写路径。
- `dashboard/prompts` **部分可行**：联调后它仍只作为 list-only 旁路；DTO 更接近 prompt template（`title/prompt_text/agent_key`），并不等同于页面原生卡片 shape（`name/content/agentType`）；前端若做 adapter，必须 best-effort，映射失败时允许保留当前列表或空态，只展示只读 banner，不得发明写/删代理。
- 当前 `SystemPromptPage` 模板内联在 `SystemPromptPage.js`，仓库里没有 `SystemPromptPage.template.js` / `SystemPromptPage.css`；文档必须以真实落点为准。
- 与 `p20.1` 联调**不需要 feature flag**：这是宿主 contract 修复 + 运行时 capability detection 问题，不是灰度特性。下一次 `prompts/list` 成功即应自动退出 fallback。
- 降级日志等级建议：**首次进入 fallback 用 `warn`，稳态重试与恢复用 `info`**；不要每次 mount / refresh 都刷 `warn`。

## 5. 实施步骤（编号 1-N）
1. 在页面内新增本地 not-found detector（`404` / `method not found` / `not found` 白名单），且**仅**对 `prompts/list` 命中时进入 fallback。
2. 404 fallback UI 行为：展示提示条；保留 `刷新` / `复制`；禁用 `+新建` / `保存` / `删除`；编辑器改为 view-only（字段 disabled，保存按钮 hidden 或 disabled）。
3. 如实现成本可控，可尝试 `dashboard/prompts` 的 list-only hydrate：`title -> name`、`prompt_text -> content`、`agent_key -> agentType` 做 best-effort 映射；若不稳妥，允许只保留 banner + 当前/空列表。
4. fallback 首次进入时记一条 `warn`；后续相同 scope 的重复探测与恢复成功记 `info`，避免噪声。
5. 任何一次后续 `prompts/list` 成功都必须自动清理 fallback 状态；不引入定时轮询，不引入额外 feature flag。

## 6. 验收标准
- 前端 behavior 测试入口：扩展 `cmd/agent-terminal/frontend/vue-app/system-prompt-page.behavior.test.js`，覆盖 `404 -> readonly -> recovery` 与 `非404 -> error`。
- 若实现了 `dashboard/prompts` adapter，则补跑 `go test ./internal/module/dashboard/...`，确认只读旁路 response shape 仍可消费。
- 最终保持前端 `vitest`、`go build ./...` 绿色；不得新增 browser-native 文件写入 fallback，不得新增跨层依赖。

## 7. 风险与回退
- 风险：若把所有错误都吞掉，会掩盖真实异常。回退：仅对白名单 404/not-found 走 fallback，其余错误继续暴露。
- 风险：`dashboard/prompts` 的 DTO / 业务语义与 SystemPromptPage 不完全对齐。回退：只保留 banner + readonly 空态/当前态，不强行映射。
- 风险：重复 `warn` 形成日志噪声。回退：仅首次进入 fallback 记 `warn`，稳态重试/恢复改 `info`。
