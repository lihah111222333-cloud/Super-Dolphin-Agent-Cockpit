# MCP：把 `skill_list` / `skill_expand` 注册到 `cmd/mcp-orch`

> 创建时间：2026-04-19 | 状态：📝 审查后可派单 | 依赖：`p20.10`（`skill.Service.Expand` / name-based service）
> Agent 预算：1 个 codex agent，改动 ≤7 文件，≤400 行/文件

## 1. 目标（1-3 句）
在 `cmd/mcp-orch/tools` 按现有 resource-style 模式增加 `skill_list` / `skill_expand`，并把 skill 能力纳入 registry。此单只做 MCP tool facade，不直接复用宿主 RPC handler map。

## 2. 前置依赖
- 依赖 `p20.10` 落地 `skill.Service.Expand(...)` / name-based service 能力；**本单不复刻 expand 逻辑**。
- 本单只负责 MCP tool facade；不改 host RPC handler map，不通过 `Server.Dispatch("skill/...")` 绕接。
- 职责边界锁定为：**共享 service，不共享 handler map**；禁止直接引入 `skill.Module`，避免把 host RPC wiring 带进 `mcp-orch`。

## 3. 源码锚点（复用 `source-refs-appendix.md`）
- [SRC-A29](source-refs-appendix.md#src-a29) — 当前 MCP registry 没有 skill 依赖
- [SRC-A30](source-refs-appendix.md#src-a30) — `prompt_tools.go` 可直接借鉴 resource-style 模式

## 4. 文件清单
### 4.1 新建文件（路径 + 职责 + 行数预算）
- `cmd/mcp-orch/tools/skill_tools.go` — 定义 `skill_list` / `skill_expand` schema、MCP DTO 映射与 handler；预算 260 行
- `cmd/mcp-orch/tools/skill_tools_test.go` — schema / list / expand handler regression；预算 220 行

### 4.2 改动文件（file:line + 改点）
- `cmd/mcp-orch/tools/registry.go:11-37` — `Dependencies` 增 `skill.Service`，并注册 `skillToolDefinitions`

- `cmd/mcp-orch/fx.go:80-109` — `fx.Provide` 轻量 `skill.Service` constructor，并补 `tools/skill` capability；**禁止直接引入 `skill.Module`**

- `cmd/mcp-orch/tools/factory.go` — **仅当**需要补通用 tool helper 时才改；`skill_expand` 不能生搬 `resourceToolDefinitions()`，因为它有 `section` / `max_bytes` 扩展 schema

## 5. 实施步骤（编号 1-N）
1. 参照 `prompt_tools.go` 复用“list/get 成对导出”的命名与描述模式；但 `skill_expand` 需独立 schema（`name` + `section?` + `max_bytes?`），不要强塞进现有单-key helper。
2. 通过 `skill.Service` 直接调用 `ListSkills/Expand`；禁止复用宿主 `NewSkillHandlers()` / `handler.Map` / `Server.Dispatch()`。
3. `skill_list` 默认只返回 metadata-only 结果，显式裁掉 `SkillInfo.Dir` 这类绝对路径字段；`skill_expand` 的 description 必须写清 `section` / `max_bytes` 语义。
4. 在 fx/runtime/registry 三处打通 `skill.Service` 注入，并把 `tools/skill` 加入 bootstrap capabilities，避免 `tools/list` 与 capability 漂移。
5. 补 regression test，覆盖 registry 枚举、capabilities、not-found/error path 与 schema 一致性。

## 6. 验收标准
- 单元/behavior 测试入口：`go test ./cmd/mcp-orch/tools/... ./cmd/mcp-orch/...`；`go build ./...`、`go test ./...` 全绿；archtest 不让 `cmd/mcp-orch` 走 host-RPC selector（`internal/platform/rpc` host symbols）。

## 7. 风险与回退
- 风险 1：若在 `cmd/mcp-orch` 侧重复实现 expand 逻辑，会与 `p20.10` 形成双实现漂移。回退：统一只调用 `skill.Service.Expand(...)`。
- 风险 2：若直接引入 `skill.Module`，会把 host RPC wiring 一并带入 `mcp-orch`。回退：仅 `fx.Provide(func(cfg *config.Config) skill.Service { ... })` 轻量注入 service。
- 风险 3：若 `skill_expand` 直接套 `resourceToolDefinitions()`，会丢 `section` / `max_bytes` richer schema。回退：为 `skill_expand` 保留独立 schema builder。

### 7.1 合规结论（修订后）
- **依赖**：✅ 本单显式依赖 `p20.10` 的 `skill.Service.Expand`，不再宣称“独立”。
- **边界**：✅ host RPC 面向 UI/宿主 JSON-RPC，MCP tool 面向底层模型 tool call；两者共享 service，不共享 handler map。
- **禁止项**：✅ `cmd/mcp-orch/tools/*` 不走 `Server.Dispatch()`；`cmd/mcp-orch/fx.go` 只做轻量 service 注入，不直接引 `skill.Module`。
- **数据裁剪**：✅ `skill_list` 默认 metadata-only，不暴露 `SkillInfo.Dir` 绝对路径；`skill_expand` 使用独立 schema，不生搬 `resourceToolDefinitions()`。

## 8. 审查补遗（2026-04-19，LSP 核查）
### 8.1 代码落点结论
- `cmd/mcp-orch/tools/` 全目录无任何 `skill_` 前缀 tool，确认当前缺失。
- `cmd/mcp-orch/tools/prompt_tools.go:50-60` 证明现有 pattern 是“在 `tools/` 定义 schema + handler，再由 `registry.go` 聚合注册”。
- `cmd/mcp-orch/runtime.go:110-125` 显示 registry 依赖当前只收 orchestration/workspace/prompt/command/shared_file/memory，缺少 skill 注入位。
- `cmd/mcp-orch/fx.go:80-109` 显示 bootstrap capabilities 必须同步补 `tools/skill`；轻量 `skill.Service` 注入则继续保持在现有 Fx wiring 内，避免 `tools/list` / capability 漂移。

### 8.2 职责边界结论
- host RPC：`internal/module/skill/rpc.go` + `internal/platform/rpc/module.go` 负责 UI/宿主 JSON-RPC 注册。
- MCP tool：`cmd/mcp-orch/tools/skill_tools.go` 负责给底层模型暴露 `skill_list` / `skill_expand`。
- 两者共享 `skill.Service` 即可；**不能**共享 handler map，**不能**让 `mcp-orch` 通过 host RPC 再转一跳。

### 8.3 类型归属结论
- 归属为 **resource-style MCP tools**，不是 MCP Resource。
- 原因：当前 `cmd/mcp-orch` 只有 `tools.Registry` 暴露链；且 `skill_expand` 带 `section` / `max_bytes` 参数，语义上更像“按需读取工具”而非静态资源浏览。

### 8.4 schema / description 质量要求
- `skill_list`：返回 metadata-only 结果，默认不要把 `SkillInfo.Dir` 这种绝对路径直接暴露给模型。
- `skill_expand`：description 必须写清：
  - 什么时候该调用 / 不该调用；
  - `section` 为空、`#` 锚点、相对路径三种语义；
  - `max_bytes` 默认值与截断语义；
  - not-found 时返回可用 skill 名列表。
