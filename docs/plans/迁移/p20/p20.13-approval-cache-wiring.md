# approval：把 `(name,hash)` 审批缓存接入生产链

> 创建时间：2026-04-19 | 状态：⚠️ 审查后需按依赖收敛 | 依赖：`p20.10`（`Expand` 入口）+ `p20.6`（审批事件链）

## 1. 目标（1-3 句）
让已存在的 approval cache / event surface 真正参与 skill 生产链：未审批的 project skill 不能直接 expand，hash 变化会触发重新审批。此单不做新 UI，只补后端闭环与回归测试。

## 2. 审查结论（基于 2026-04-19 LSP）
- `internal/module/skill/approval.go:14-298` 与 `approval_test.go` 已把 `(name, content_hash)` 持久化骨架做完；但生产消费点目前只有 `service.go:38-49` 的构造期挂载，没有任何 `Lookup/Approve/Revoke` 调用。

## 6. Approval 缓存接入链
1. `p20.10` 提供的 `skill/expand(name, scope)` 进入 host skill service。
2. 用 `validateSkillName()` + `scanSkills()/ListSkills()` 解析出 `SkillInfo{Name, Trust, ContentHash}`。
3. 若 `Trust` 为 `user/signed`：直接放行，不走审批缓存。
4. 若 `Trust` 为 `project`：先查 `approval.Lookup(name, hash)`；注意这表示 **content-global `(name,hash)`**，不是项目级批准。
5. miss 时，通过 approval requester 发起：
   - `Kind: "skill"`
   - `SourceMethod: "skill/requestApproval"`
   - `ToolName: "skill_expand"`
   - payload 至少包含：`name`、`content_hash`、`trust`、`scope`、`skills_dir/project_root`、`threadId/sessionId`
6. 审批通过后：
   - `scope=project`：`approval.Approve(name, hash, trust, approvedBy)`
   - `scope=session`：只写内存态，不落盘；绝不能写入 `ApprovalCache`
7. 返回 expand 结果；hash 变化时因为 `Lookup(name,newHash)` miss，会自动强制重审。
