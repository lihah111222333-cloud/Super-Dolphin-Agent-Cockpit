# skill 链路 cwd 参数化：修复跨项目泄漏 + 前后端 cwd 契约补齐

> 创建时间：2026-04-20 | 状态：⏳ 待实施（等 p20.13 合入后派实施 agent）| 依赖：`p20.10`（skill/expand）+ `p20.13`（approval gate 接线；避免 rpc/service 文件冲突）+ `p20.15`（dashboard cwd 前端契约经验）
> Agent 预算：1 个 codex agent，改动 ≤9 文件；`internal/module/skill` 经 p20.13 合入后预期 ~20 Go 文件 / ~3600 EL（走 freeze 默认 25 / 10000，若越线需独立单调整 freeze）

## 1. 目标（1-3 句）

让 `skills/list` / `skill/list` RPC 与 `service.ListSkills` 支持 per-request `cwd` 参数，并让 `scanSkills` 识别 `~/.super-dolphin/skills/<project-key>/by-id/<skill>/SKILL.md` 的项目隔离结构，按当前 cwd 对应的 project-key 过滤，杜绝跨项目 skill 泄漏。配套前端 picker 改为按 `useActiveCwd` 传 cwd。hydrate 失败时的 UX 警告块（原选项 D）**不在本单范围**，留给后续单 p20.19 按 p20.17 合入后的运行时数据决定是否需要。

## 2. 现状诊断（基于 2026-04-20 运行时实证）

- **存储结构**：`~/.super-dolphin/skills/` 下实际为 `<project-key>/by-id/<skill-name>/SKILL.md`（`cmd/mcp-orch/memory/path.go:45,165-192` 的 `sanitizePath` 生成 project-key，如 `wj_langgraph`、`Users_mima0000`、`bot_super-agent-v3`）。当前宿主机共 175 个真实 SKILL.md，分布在 9 个 project-key 下 + 1125 个测试遗留 `tmp_*` / `TestCLIClient*` 空目录（只有 `.cwd-owner`）。
- **跨项目泄漏**：`internal/module/skill/skills_meta.go` 的 `scanSkills()` + `visitSkillEntry()` 用 `filepath.WalkDir` 递归整个 `root`，不按 project-key 过滤；`resolveSkillRecordByName` 再按 name 精确匹配（`skills_fs.go` `resolveSkillRecordByName`），同名 skill 跨项目随机命中。
- **RPC 契约缺 cwd**：`skills/list` / `skill/list` handler 参数类型 `struct{}` / `skillListParams`（`internal/module/skill/rpc.go` `NewSkillHandlers`），**不接 cwd**；`service.ListSkills(ctx)` / `scanSkills()` 签名不含 cwd；service 仅凭构造期 `cfg.ProjectRoot`（`internal/module/skill/module.go:20-30` `newService`）决定 `projectSkillsRoot`，per-request 无法切换。
- **前端也不传 cwd**：`cmd/agent-terminal/frontend/vue-app/services/skills-api.js:3-6` `listSkills()` 调 `callAPI('skills/list', {})`；`composables/useLaunchSkillSelection.js:123` 直接消费，无 cwd 参数。对照 p20.15 的 `dashboard/prompts` 已改为 `{ cwd }` 传参，skill 链路**落下未对齐**。

## 3. 前置依赖 & 范围边界

### 3.1 实施前置

- **必须**：`p20.13`（approval gate）已合入并在 main。p20.17 与 p20.13 都碰 `rpc.go` / `rpc_skill_types.go` / `service.go` / `skills_fs.go`，不得并行。
- **参考**：`p20.15-prompts-picker-cwd.md`（前端 `useActiveCwd` + 后端 `ListFilter.CWD` 的契约范式）。
- **复用**：`internal/platform/shared/project_key.go` 统一承载 project-key 逻辑，但要保留**两套独立算法**：`SanitizeMemoryProjectKey`（memory / mcp-orch 旧语义：全路径 dash-slug 小写）与 `SanitizeSkillProjectKey`（skill 新语义：段分隔 + 保留大小写）。`autoDreamProjectKey` 保持 full canonical path 语义，不走任何 `Sanitize*` / `*ProjectKeyFromCwd`。

### 3.2 不在范围内

- **不改** `skills/match/preview` 的匹配语义：本单仅补 cwd 透传与必填校验，不扩 preview 的 project filter 规则。
- **不改 skill 存储布局**：现存 `~/.super-dolphin/skills/<project-key>/by-id/<skill>/SKILL.md` 结构保持；本单只改**扫描侧** project-key 过滤。
- **不做清理脚本**：1125 个测试遗留空目录应由 `p20.18-skill-root-cleanup`（后续单）处理，不在本单内，以免写入操作污染本单 diff。
- **不做 hydrate failure UX warning**（原选项 D）：已移出本单范围，待 p20.17 合入后视运行时反馈决定是否起 `p20.19`。
- **不触 approval cache 语义**：p20.13 的 `(name, hash)` / artifact-level cache key 不受 project-key 影响（content-global 按设计）。

## 4. 源码锚点（用函数名锚定，避免 p20.13 合入后行号漂移）

- `internal/module/skill/module.go` `newService` — 当前仅吃 `cfg.ProjectRoot`；需改为 per-request cwd 可覆盖。
- `internal/module/skill/service.go` `NewService` / `defaultProjectSkillsRoot` / `skillRoots` / `ListSkills` — 加 `cwd` 参数，cwd 非空时覆盖构造期 `projectSkillsRoot`；`skillRoots(cwd)` 按 cwd → project-key 派生扫描根。
- `internal/module/skill/skills_meta.go` `scanSkills` / `visitSkillEntry` — 支持 `<systemRoot>/<project-key>/by-id/*/SKILL.md` 三层结构识别；未匹配 project-key 的子树直接 `filepath.SkipDir`，不走 parseSkillRecord。
- `internal/module/skill/skills_fs.go` `resolveSkillRecordByName` — 按 cwd（从 `ctx` 取）过滤后再 name 精确匹配；cwd 缺失返回 `ErrMissingCWD`。
- `internal/module/skill/rpc.go` `NewSkillHandlers` — `skill/list`、`skills/list`、`skill/expand`、`skills/local/*`、`skills/expandBody`、`skills/readResource` 全部 handler 参数补 `cwd`；当前不接 cwd 的方法里，`struct{}` 改成 `skillListParams{CWD string}`，兼容前端只传 `{ cwd }`。
- `internal/module/skill/rpc_skill_types.go` `skillListParams` / `skillExpandParams` / `ExpandBodyParams` / `ReadResourceParams` — 统一加 `CWD string json:"cwd,omitempty"` 字段；JSON `omitempty` 仅保证旧客户端不传字段时能反序列化，**handler 拿到空 cwd 立即返回 `InvalidParams`（`ErrMissingCWD`）**，不再提供全局扫描降级。
- `internal/platform/shared/project_key.go`（新建）— 导出 `ProjectKeyFromCwd(cwd string) string`（skill 语义）与 `MemoryProjectKeyFromCwd(cwd string) string`（memory 语义）；其中 `SanitizeMemoryProjectKey` 必须 byte-for-byte 等价旧 `sanitizePath`，`SanitizeSkillProjectKey` 对齐 skill 磁盘目录名。
- `cmd/agent-terminal/frontend/vue-app/services/skills-api.js` `listSkills` — 签名改 `listSkills(cwd)`，`callAPI('skills/list', { cwd })`。
- `cmd/agent-terminal/frontend/vue-app/composables/useLaunchSkillSelection.js` — 调用处注入 `useActiveCwd().value`（对齐 p20.15 `useSystemPromptPage` 的做法）。
- `internal/module/prompt/skill_catalog_provider.go` `Resolve` — `errors.Is(err, skillpkg.ErrMissingCWD)` 直接上抛 err（契约违反 fail-fast）；其他 scan 失败保持原"不注入 manifest + 不阻断装配"容忍口径。
- `internal/module/turn/skills.go` `hydrateSkillRefs` / `skillHydrationIndex` — 签名改为 `(refs, error)` / `(ctx, index, error)`；`ErrMissingCWD` 向上抛让 `PrepareTurn` 返 err 给 RPC 层映射 `InvalidParams`；其他 err 保持原容忍。
- `internal/module/turn/service.go` `PrepareTurn` — 接住 `hydrateSkillRefs` 的 err 并 return，不再无条件赋值 `input.Skills`。

## 8. 风险 & 回退

### 8.1 风险

- **sanitizePath 算法跨模块不完全一致**：mcp-orch 与 skill 的 key 若规则差 1 个字符，会导致 skill 扫描端找不到 mcp-orch 写入端的目录。**必须**抽到 `shared` 统一来源，**不接受**"skill 侧重新实现一版"。
- **caller 升级成本**：CLI / 单元测试 / dashboard / prompt / turn / 前端若遗漏 cwd，会立刻得到 `ErrMissingCWD`；必须逐调用点补齐，不能再依赖默认全局扫描。
- **p20.13 合入前不得启动本单**：两单都改 `rpc.go` / `service.go` / `skills_fs.go` / `rpc_skill_types.go`，并行会 merge conflict；必须串行。
- **freeze 越线风险**：如果 shared/project_key 新增后 `internal/module/skill` 文件数 +3 或 EL +400，超 freeze 默认 25 / 10000 → 需独立 freeze commit。

### 8.2 回退

- 按 Step A-D 4 个 commit 反向 revert 即可；Step E 只是验证不产生 commit；每 Step 独立 build/test 绿，回退不带脏状态。
- 若运行时发现 project-key 派生对某特殊 cwd（如 symlink / 相对路径）匹配不上，应修正 caller 传入的 cwd / git root 规范化逻辑；不再提供 `cwd == ""` 的降级口。
