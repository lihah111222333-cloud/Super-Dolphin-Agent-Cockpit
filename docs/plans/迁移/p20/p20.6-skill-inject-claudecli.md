# claudecli Port：实现 skill 注入并处理 Native Skills 降级

> 创建时间：2026-04-19 | 状态：⚠️ **基础已落地**（`9b0f7e1`/`9707764`），per-turn carrier/registry 集成待收口 | 依赖：p20.4 ✅
> 审查日期：2026-04-19 | 结论：Port 路径对，但当前文档缺 carrier / registry / trim 兼容说明
> ⏹ **进度备注**：`internal/contract/skill_injection.go` 共享契约 + `internal/provider/claudecli/skill_inject.go` 实现（含 native scan）已在 P20.1 Phase 7 落地。剩余工作：per-turn `SkillPrompt` carrier + provider-name registry + `session_turn.go` 消费收口。

## 1. 目标（1-3 句）
把 claude provider 的 per-turn skill 注入从 `session_turn.go` 中抽出来，并按实验 B 固化 native-skill 降级策略：`.claude/skills/*` 由 Claude 原生注入，harness 不重复投全文。

## 2. 审查结论（先看这个）
- `internal/provider/claudecli/session_turn.go:315-351` 当前只消费 `SkillRef.Name` 和 `SkillRef.Prompt`；`Mode/Summary/Source` 虽已在 `internal/dto/provider/turn.go:43-104` 落地，但 claude 写端尚未使用。
- `docs/研究材料/实验验证/p20-exp-b-claudecli-native-skills.md:37-64` 已锁定：**没有可用 CLI flag 能关闭 Claude 原生 skills 自动发现**。因此 `.claude/skills/<name>/SKILL.md` 命中时必须显式 `Mode=None`，同名冲突 native 优先。
- `SkillInjectionPort` 放 `internal/contract/skill_injection.go`、claude 实现放 `internal/provider/claudecli/skill_inject.go` 是对的；但**当前文档少了 module 调用所需的 generic carrier**。如果 port 产出 turn skill section，结果必须通过通用 DTO 字段传递；否则仍会退回 provider 本地拼装，违背“module 调用、module 不 import provider”的约束。
- `buildSkillList()` 现有 `skills:\n- name` 是 native skill 的正确兜底：`Mode=None` 时要保留 name list，只禁止 body 重投；不能把 name 也丢掉。
- `internal/provider/claudecli/history_trim.go:16-22,63-95` 仍按 legacy marker（`[skill:] + 摘要: + 使用方式:`）剥离 skill block。若 p20.6 改 summary 格式但不同时补 trim 兼容，rollout/history 会污染。
- `internal/provider/claudecli/config.go:52-69` + `transport_config.go:127-155` 已证明启动期 `BaseInstructions` 会被物化成 `--system-prompt`；因此 **L1 catalog 仍由 p20.5 通过 prompt assembly 注入，p20.6 不应再做一份 claude-only L1 重复注入**。

## 5. Claude Native Skills 冲突策略（锁定版）
1. 扫盘根：优先 `gitRoot`，再退回 `cwd`；检查 `.claude/skills/<name>/SKILL.md` 是否存在。
2. 命中 native：强制 `SkillRef.Mode = None`、`SkillRef.Source = Native`，清空 body/summary carrier；**name 保留**，让 `skills:` list 继续可见。
3. 同名冲突：`.claude/skills/<name>` 与 `.agent/skills/<name>` 同时存在时，**native 优先**，避免双重加载。
4. L1 catalog：仅标元数据来源（`Native (Claude-provided)` / `Custom (harness-provided)`），不重复注 body。
5. `skill_expand`：native skill 不走 harness expand；返回明确提示 `use native "/skill-name" instead`。

## 6. 实施步骤（修订后）
1. 先补 `internal/contract/skill_injection.go` 与 fx group registry，保证 module 只依赖 contract。
2. 在 `dto.TurnRequest` / `SteerRequest` 增加通用 carrier，让 turn module 能真正“调用 port”。
3. 在 `internal/module/turn/service.go` 解析 provider-specific port，写入 `req.SkillPrompt`；无 port 时保留 legacy fallback。
4. 在 `internal/provider/claudecli/skill_inject.go` 实现 full/summary/none + native scan；summary 渲染先保持 legacy `摘要:` / `使用方式:` marker，直到 `p20.9` 读端 helper 合并后才允许切写端 gate。
5. 收敛 `session_turn.go` 为“消费 carrier + 保留 name list fallback”的薄层；`.claude/skills/<name>/SKILL.md` 命中时只禁 body，不丢 `skills:` name list。
6. 补 native 优先、同名冲突、history trim、steer/no-double-inject 回归测试；native scan 根路径固定 `gitRoot > cwd`。

## 7. 验收标准
- 分层：`internal/module/turn` / `internal/module/thread` 不 direct import `internal/provider/claudecli`
- 行为：`Mode=Full` 注全文；`Mode=Summary` 注摘要 + expand 指引；`Mode=None` 仅保留 `skills:` name list
- 冲突：native skill 命中时不重复注 body；同名 native/custom 以 native 为准
- 守卫：`go test ./internal/provider/claudecli/... ./internal/module/turn/...` 绿；`go test ./internal/archtest -run 'TestDependencyDirection|TestWave3DependencyDirection|TestCodeSizeGuard'` 绿
- 兼容：旧 payload 不带 `skillPrompt` 仍可工作；旧 history trim 不被新 summary block 破坏

## 8. 风险与回退
- 风险 1：若不补 generic carrier，所谓“module 调用 port”会落空，最终仍是 provider 本地拼接；**回退策略：先补 `SkillPrompt` carrier，再落地 port**。
- 风险 2：若 summary block 改格式但 trim 不改，rollout/history 会残留 skill 噪声；**回退策略：在 shared rollout markers 落地前保留 legacy `摘要:` / `使用方式:` marker**。
- 风险 3：native scan 若只看 `cwd` 不看 `gitRoot`，worktree/子目录会漏判；**回退策略：根路径判定按 `gitRoot > cwd`**。
- 风险 4：若在 p20.6 再做一次 claude-only L1 manifest 注入，会与 p20.5 重复；**回退策略：明确 L1 仍走 prompt assembly，本单只做 per-turn port 与 native 降级**。

- **claudecli 包预算**：⚠️ 按本轮审查口径 `24→25`，因此 claudecli 侧**只能新增 `skill_inject.go`**，测试优先并入现有文件。
- **Native Skills 语义**：✅ 命中 `.claude/skills/<name>/SKILL.md` 时强制 `Mode=None, Source=Native`；保留 `skills:` name list，只禁 body，`skill_expand` 返回 native 指引。
- **rollout 兼容**：✅ 在 `p20.9` 读端 helper 合并前，写端继续保持 legacy marker 可被 `history_trim.go` 识别，不抢跑新 marker。
