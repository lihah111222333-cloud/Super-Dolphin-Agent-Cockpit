## 4. 实现方案

### 4.1 可复用模块

- 事件总线可直接复用。V3 已有统一 `event.Dispatcher`、typed emitter 和 resilient subscribe，适合做 `uistate` projector 的底座，而不是再造一套 dashboard 专用 bus，[internal/platform/bus/bus.go:14](/Volumes/bot/super-agent-v3/internal/platform/bus/bus.go#L14) [internal/platform/bus/emitters.go:32](/Volumes/bot/super-agent-v3/internal/platform/bus/emitters.go#L32) [internal/platform/bus/resilient.go:10](/Volumes/bot/super-agent-v3/internal/platform/bus/resilient.go#L10)。
- “bus event -> push” 这段也可复用。RPC 侧已有 `PushBridge.NotifyClient` / `NotifyAll`，Wails 侧已有 `EventBridge.publish`；如果未来要补 dashboard 刷新事件，优先在同一 projector 上发新 DTO，而不是在 UI 层重复监听底层事件，[internal/platform/rpc/push.go:35](/Volumes/bot/super-agent-v3/internal/platform/rpc/push.go#L35) [internal/platform/rpc/server.go:67](/Volumes/bot/super-agent-v3/internal/platform/rpc/server.go#L67) [internal/ui/wails/bridge.go:81](/Volumes/bot/super-agent-v3/internal/ui/wails/bridge.go#L81)。
- 桌面请求入口也可直接复用。Wails `App.CallAPI -> server.Dispatch` 已经打通本地 RPC，不需要为了 dashboard 再起一个本地 HTTP server，[internal/ui/wails/binding.go:22](/Volumes/bot/super-agent-v3/internal/ui/wails/binding.go#L22) [internal/platform/rpc/server.go:43](/Volumes/bot/super-agent-v3/internal/platform/rpc/server.go#L43)。
- 如果后续确实要支持远端/浏览器客户端，现成 `WSHandler` + `AllowPush` 是更自然的第二传输层；这条链路已经存在，不必先做 SSE，[internal/platform/rpc/transport_ws.go:21](/Volumes/bot/super-agent-v3/internal/platform/rpc/transport_ws.go#L21) [internal/platform/rpc/server.go:183](/Volumes/bot/super-agent-v3/internal/platform/rpc/server.go#L183)。

## 结论

V3 做 dashboard 是可行的，但“可行”的前提是先把范围收窄到桌面 Wails 优先，而不是复制 V2 的独立 HTTP/SSE dashboard。现有 V3 已经具备 bus、jrpc2 push、Wails bridge、local dispatch 四块底座，[internal/platform/bus/bus.go:14](/Volumes/bot/super-agent-v3/internal/platform/bus/bus.go#L14) [internal/platform/rpc/push.go:75](/Volumes/bot/super-agent-v3/internal/platform/rpc/push.go#L75) [internal/ui/wails/bridge.go:42](/Volumes/bot/super-agent-v3/internal/ui/wails/bridge.go#L42) [internal/ui/wails/binding.go:22](/Volumes/bot/super-agent-v3/internal/ui/wails/binding.go#L22)；真正缺的是 `module/uistate`、`module/dashboard` 和实际前端资产，[cmd/mcp-orch/orchestration/rpc.go:1](/Volumes/bot/super-agent-v3/cmd/mcp-orch/orchestration/rpc.go#L1) [internal/ui/wails/frontend/index.html:48](/Volumes/bot/super-agent-v3/internal/ui/wails/frontend/index.html#L48)。

如果目标是 P7w2 交付一个能在 P6 Wails 层跑起来的 V3 dashboard，建议路线是：先做 `uistate` projector 和 `dashboard` handler map，再接 Wails `bridge-event` 与页面资产；SSE/独立 web dashboard 留到后续单独波次。否则一旦同时追平 V2 的 HTTP/SSE、WS、桌面前端三条路径，工作量会直接落到悲观区间。
