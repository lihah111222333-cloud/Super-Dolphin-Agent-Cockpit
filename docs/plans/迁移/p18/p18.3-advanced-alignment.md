## Phase E：claudeMd 多来源注入链（P1，5-7 天）

> 状态：✅ 已完成（提交：cc28e11） | 锚点：`internal/module/memory/claudemd_sources.go`、`internal/module/prompt/user_context_builder.go`

### 依赖：P18.2 D-5（UserContextText 格式对齐）、C-1（门禁快照）、C-4（truncate helper）、A-3（生命周期失效入口）

### 问题

Claude 的 `getUserContext().claudeMd` 是 **9 步来源聚合**：
1. Managed `CLAUDE.md`
2. Managed rules
3. User `CLAUDE.md`
4. User rules
5. Project（`CLAUDE.md` + `.claude/CLAUDE.md` + unconditional rules，root→cwd）
6. Local（每层 `CLAUDE.local.md`）
7. `--add-dir`
8. AutoMem
9. TeamMem

V3 只有单根 `MEMORY.md` fallback，且缺 source filter / memoized base payload / parse pipeline / source-manifest 失效合同。

### 任务清单

#### E-1：Source Resolver

| 文件 | 改动 |
|------|------|
| 新建 `internal/module/memory/claudemd_sources.go` | `ResolveClaudeMdSources(ctx, cfg) []ClaudeMdSource` |
| `ClaudeMdSource` | `{ Path, Content, Type(managed/user/project/local/automem/teammem), Description, Origin, Conditional, Globs, BaseDir, RuleScope }` |

来源发现顺序：
1. Managed `CLAUDE.md`
2. Managed `.claude/rules/*.md`（unconditional only）
3. User `CLAUDE.md`
4. User `.claude/rules/*.md`
5. Ancestor walk（root→cwd）：每层先加载 `CLAUDE.md`、`.claude/CLAUDE.md`、`.claude/rules/*.md`（unconditional only）
6. 同层再加载 `CLAUDE.local.md`
7. `--add-dir` 额外目录（受 feature gate）
8. AutoMem `MEMORY.md`（经 `ParseMemoryFile()/sanitize + TruncateEntrypointContent`）
9. TeamMem `MEMORY.md`（经 `ParseMemoryFile()/sanitize + TruncateEntrypointContent`）

补充约束：
- nested worktree 时，仅跳过 worktree 之上的 checked-in Project sources；Local 仍保留
- `AutoMem/TeamMem` 读取禁止直接裸 `os.ReadFile`
- `ClaudeMdSource` 必须保留 conditional / globs / baseDir 等 rule metadata，供 Phase L 复用；禁止在 E 阶段把 rule source 降维成只剩正文
- 本 Phase 只处理 **memory 内容注入链（claudeMd）**，不改变 `loadMemoryPrompt()` 的规则 prompt 分派

#### E-2：Source Filter

| 文件 | 改动 |
|------|------|
| `claudemd_sources.go` | `FilterInjectedMemoryFiles(sources, gate, excludes) []ClaudeMdSource` |

三层过滤：
1. **Per-file gate**：`claudeMdExcludes` 仅作用于 `User/Project/Local`
2. **Injected filter**：消费 `MemoryGateSnapshot.InjectMemoryIndex`；当其为 false（输入之一是 `SkipIndex=true` / `tengu_moth_copse`）时过滤 AutoMem/TeamMem
3. **Final render gate**：`tengu_paper_halyard` 跳过 `Project/Local`

补充约束：
- `Managed/AutoMem/TeamMem` 永不受 `claudeMdExcludes` 影响
- `FilterInjectedMemoryFiles()` 只做筛选，**不得丢失** `Conditional/Globs/BaseDir/Origin` 等 source metadata
- filter 结果要可复用给 Phase L nested source resolver

#### E-3：Renderer

| 文件 | 改动 |
|------|------|
| 新建 `internal/module/prompt/user_context_builder.go` | 拆成 `BuildBaseUserContext()` / `CollectRuntimeUserContext()` / `MergeRuntimeUserContext(base, extras)` / `FormatUserContextMessage(map)` |

输出格式：
- `<system-reminder>`
- `# claudeMd`
- 每个来源：`Contents of {path}{description}: ...`
- TeamMem 包 `<team-memory-content source="shared">`
- `# currentDate`
- `Today's date is YYYY-MM-DD.`
- `# runtimeExtras`
- relevance disclaimer
- `</system-reminder>`

补充约束：
- `BuildBaseUserContext()` **只负责 claudeMd/source payload**，不再把 `currentDate` 放进 memoized base payload
- base cache key 只绑定**影响 claudeMd 渲染结果的 gate 子集**（如 `InjectMemoryIndex` / `DisableClaudeMds` / add-dirs / excludes）以及 source manifest digest(path+mtime/size)
- `FormatUserContextMessage(map)` 必须固定 key 顺序：`claudeMd -> currentDate -> runtimeExtras -> disclaimer`
- `UserContextText` 的语义是 synthetic user meta message body，不是普通 user text

#### E-4：接入 AssembleTurn

| 文件 | 改动 |
|------|------|
| `internal/module/prompt/assembler.go` | `AssembleTurn()` 的唯一数据流固定为：`base := BuildBaseUserContext(...) -> extras := CollectRuntimeUserContext(...) -> merged := MergeRuntimeUserContext(base, extras) -> UserContextText := FormatUserContextMessage(merged)`；`runtimeExtras` 明确聚合到单独 key，不得散落到别的 section |
| `internal/module/thread/post_compact_cleanup.go` / `internal/module/prompt/assembler.go` | base user-context cache / memory-source cache 的清理与重建点统一接到 Phase I / Phase A-3 生命周期；provider 只透传 `UserContextText`，不再二次包装 |

**验收标准**：
- turn user context 按 9 步顺序聚合 claudeMd 来源，且按层 interleave project/local
- TeamMem source 在 renderer 阶段做 XML wrap
- `SkipIndex`、`claudeMdExcludes`、`tengu_paper_halyard` 三类过滤都生效且边界正确
- `UserContextText` pipeline 与 `RelevantMemoryAttachment` / transcript fallback / nested attachment pipeline 严格分离
- source-manifest 变化会驱动 base payload 失效或重建，不会把旧 `currentDate` / 旧 claudeMd 缓到下一个 turn
