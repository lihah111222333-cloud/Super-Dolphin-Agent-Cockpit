## Phase A：Turn 上下文补全 + Cache 语义改造（P0，2-3 天）

> 状态：✅ 已完成

### 问题

1. `turn/service.go:99-108` 只传了 `CWD/Model/UserText/MCPSnapshot`，**缺失 7 个 BuildCtx 关键字段，且 `MCPSnapshot` 仍缺 `Tools/Instructions` 两个子字段**
2. cache key 是 `section.name + sha256(全量 TurnInput)`，几乎每轮 miss
3. 10 个 dynamic slot 被标成 `volatile`，Claude 只有 `mcp_instructions` 是 DANGEROUS
4. 失效触发点缺 `/clear`、`/compact`、worktree enter/exit、resume worktree restore/exit、setup flip

### 任务清单

> 架构约束：`TurnInput` 的补全仅用于提供 turn-time context builder 的 typed 数据源，**不等于**这些字段都必须进入 `UserContextText`。这些 typed 字段优先服务 `env_info_simple / language / mcp_instructions / provider filter`，只有被 D-5/E 显式纳入的 key 才进入 `UserContextText`。`AdditionalWorkingDirectories` 仅用于 working-path/env parity，**不是** future nested-memory 的 target-path 触发输入。

#### A-1：补全 Turn 上下文喂参

| 文件 | 改动 |
|------|------|
| `internal/module/turn/contract.go` | `PrepareInput` 增加 `Language/Provider/GitRoot/IsWorktree/EnabledTools/AdditionalWorkingDirectories/SessionFlags`，并补 typed `MCPSnapshot` / runtime snapshot 来源契约 |
| `internal/module/turn/factory.go` / `internal/module/turn/rpc_helpers.go` / `internal/module/turn/orchestration_starter.go` | 补齐入口喂参与 hydrate helper，避免 `Language`、`MCPSnapshot.Tools/Instructions` 在入口层丢失 |

**验收标准**：
- turn 路径的 `env_info_simple` 不再误报 git=no / LSP=not enabled

## Phase B：Prefetch 接线修正 + Freshness 展示链（P1，2-3 天）

> 状态：✅ 已完成

### 依赖：Phase A 完成（其中 B-4 需等待 C-1 门禁契约冻结）

### 问题

1. prefetch 在 `TurnStarted` 后才启动，但 `AssembleTurn()` 在之前就消费 → 拿不到当前 turn 结果
2. 消费载体错用 `UserContextText`，应改为 provider-neutral attachment/hint
3. V3 有 `UpdatedAt` 但没有展示给模型 → 旧记忆无降权
4. `search past context` 仍停在半成品：只做了 runtime memory prefetch，缺 transcript fallback 与 feature gate 激活

> 边界约束：relevant memory / transcript fallback / freshness **只走 attachment/hint**，不得回流 `UserContextText`；Phase B 的 surfaced 去重与 attachment 冻结规则是 P18.3 F-4 / Phase I 的前置约束。

### 任务清单

#### B-1：Prefetch 接线修正

| 文件 | 改动 |
|------|------|
| `internal/module/turn/service.go` | `PrepareTurn()` 里解析 `userText` 后**立刻异步启动** `StartRelevantMemoryPrefetch(ctx, ...)`，不再等 `TurnStarted`，并继承 turn-scoped ctx |
| `internal/module/memory/rules_provider.go` | `MemoryContextProvider.Resolve()` 移除记 query / 启动 prefetch 等 side effect；只保留过渡态 entrypoint/fallback 渲染，不承担 attachment builder 职责 |
| `internal/module/memory/module.go` | 移除 `TurnStarted` 订阅里的 prefetch 启动逻辑 |
| `internal/module/turn/service.go` | `PrepareTurn()` 的顺序固定为：parse userText → async `StartRelevantMemoryPrefetch()` → tool-result lifecycle cleanup → `ConsumeIfReady()` → freeze `RelevantMemoryAttachment` → provider 调用；`SteerTurn()` 复用同一 non-blocking 策略 |

**验收标准**：
- 同一 turn 内，prefetch 结果可被消费
- 不再依赖 `TurnStarted` 事件触发 prefetch
- provider 侧只消费 attachment/hint，不再把 relevant memory 拼回 `UserContextText`
- `StartRelevantMemoryPrefetch()` / `ConsumeIfReady()` 都是 non-blocking；turn interrupt / provider abort 可取消 in-flight prefetch

#### B-2：Freshness 展示链

| 文件 | 改动 |
|------|------|
| 新建 `internal/module/memory/freshness.go` | `memoryAgeDays()` / `memoryAge()` / `memoryFreshnessText()` / `memoryHeader()` |
| 新建 `internal/module/memory/retrieval_render.go` | 在 attachment / hint renderer 上应用 `memoryHeader()`，并在 surfacing/consume 时冻结 header |

**freshness 语义**：
- fresh（<=1 天）→ `Memory (saved today|yesterday): {path}:`
- stale（>1 天）→ `memoryFreshnessText + 空行 + Memory: {path}:`
- stale warning 必须明确：memory 不是 live state，file:line citation 可能已过期，断言前先核对当前代码
- freshness header 的 budget 计入 relevant-memory / transcript attachment 预算，不计入 F-5 `token_budget` 的输出目标统计

**验收标准**：
- relevant memory hints / attachment 带有 freshness header
- >1 天的 memory 有明确 stale 降权提示
- header 在 surfacing 时预生成，仅供 attachment/hint retry 复用，不进入 prompt cache / `UserContextText`

#### B-3：surfaced 去重骨架

| 文件 | 改动 |
|------|------|
| `internal/module/memory/prefetch.go` | 引入 thread-session 级 `alreadySurfaced` set，并补 `ResetSurfaced(reason)` |
| `internal/module/memory/retrieval.go` | selector 前先过滤 `alreadySurfaced`；多目录 merge 后再按 `readFileState` + `alreadySurfaced` 二次过滤 |
| `internal/module/memory/rules_provider.go` | consume 前按 `readFileState` 做最终过滤，幸存项再写回 `alreadySurfaced`；prefetch 阶段禁止提前写回 read-state |

**验收标准**：
- 同一 memory 在 session 内不重复 surfacing
- surfaced 去重遵循 selector 前 / merge 后 / consume 前三段式过滤
- `/clear`、compact/FRC stale tool-result cleanup、worktree switch、resume_restore、provider switch 都会同步 reset surfaced ledger

#### B-4：runtime search past context 闭环

| 文件 | 改动 |
|------|------|
| `internal/module/memory/retrieval.go` | 明确 `search past context` 走 runtime retrieval / attachment，不新增 Claude 式 grep prompt 文案 |
| `internal/module/memory/config.go` | `SearchPastContextEnabled` / `EnableRelevantPrefetch` 接上真实 feature gate（含 `MULTI_AGENT_MEMORY_FEATURE_SEARCH_PAST_CONTEXT`），并复用 C-1 的 gate contract |
| `internal/platform/historyjsonl/history.go` / `internal/provider/claudecli/history.go` | memory 未命中或低置信时，补 transcript fallback retrieval，输出 budget 受限的 transcript attachment/hints |
| `internal/module/memory/rules.go` | 同步收敛 `searching past context` 文案，声明 V3 依赖 runtime 检索而非提示模型自己 grep 历史 |

**验收标准**：
