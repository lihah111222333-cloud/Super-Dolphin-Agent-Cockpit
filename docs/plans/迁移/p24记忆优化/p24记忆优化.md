## 术语表

下文混用术语在此固定；函数名 / op 名 / JSON 字段名仍保留英文：

| 术语 | 中文 | 含义 |
|---|---|---|
| readback | 写后读 | 写入磁盘后立即重读以确认落盘并合成 RPC 响应；下文叙述统一用「写后读」 |
| harness | 运行壳 | 决定 entrypoint 注入与 overlay 抑制的运行时身份（generic / claude_code / codex） |
| sentinel | 哨兵错误 | `errors.Is` 可识别的导出错误值，用于 RPC 边界归一化 |
| slug | 锚点 | 跨文件追踪 backlog 的短键（源码 `TODO(tracker:<slug>)`） |
| redact | 脱敏 | RPC 边界把含路径错误替换为 sentinel，原 cause 仅入日志 |
| oracle | 信号 | 攻击者借响应差异区分两种内部状态（NotFound vs Containment 即典型 oracle） |
| pathsafe | 路径安全 | 内存读单一防御性原语 `SafeReadEntrypoint(root, rel)`（`memshared` 包） |
| containment | 围栏 | EvalSymlinks 后路径仍在 root 内的强制断言 |
| fold | 合入 | 把审查 Should-fix 合到下一轮一并修复，避免单独阶段 |
| frontmatter | 头部元数据 | `---` 围栏内的 YAML/键值，约束 mode/scope 等 ACL 字段 |
| scope ACL | 作用域访问控制 | private / team 边界，private 不可触 `team/*` |

3. **`UIAgentMemoryDetail.WriteCommittedReadbackFailed` 三态语义不足**。现为 `bool + omitempty`，false 被省略。
   - **代码事实**：当前 `saveUIAgentMemory` 只在写后读失败路径显式赋 `true`（`ui_rpc_mutations.go:324`）；`readUIAgentMemory` 与 save 成功路径都不赋值，都是零值 false 被 omit。代码注释仅定义了 `true=失败`，false 与「缺失」的语义未被代码区分。

   - **改造路径**：字段改 `*bool` 三态——nil = 写后读未发生（只读路径，字段缺省）、true = 写后读发生但失败（需重读）、false = 写后读发生且成功（快照可信）。**save 成功路径须显式赋 false**（否则仍是 nil、与只读路径不可区）；代码注释同步补三态语义定义。

     ```bash
     rg -n 'WriteCommittedReadbackFailed' --type go
     ```

**Fuzz 驱动的带路 3 轮迭代**：

1. 初版（仅加 inCDATA + 加表驱动）——`<!----><!--0\n-->0` 出 idempotent fail。根因：原 `htmlCommentLinePattern.ReplaceAllString` regex 单次 lazy 匹配，留下未闭 `<!--0\n` 作 plain。
2. 二版（stripInlineComment 改 loop 加 unclosed-tail 转 pending）——`<!--\n--> <!--0-->` 出 idempotent fail。根因：processPendingLine 的 residue 直接 append，未清理其中 closed inline。
3. 三版（抽 `emitCommentResidue` 共享逻辑 + 递归剪 closed）——`<!----><!<!---->---->` 出 idempotent fail。根因：emitCommentResidue 在剧本拼接时，前后字节息合拼成新的 `<!--...-->`（这是「删后拼接」本质上不可避免的 artifact）。
4. 终版：加 `StripHTMLComments` 包一层 fixed-point loop。每次调 `stripHTMLCommentsScan`，`stripped=false` 或 `next==content` 即收敛。Termination：每次生效迭代至少删 1 个字节，最多 `len(content)` 次。实测 7.7M 次 fuzz 运行（0 fail / 20s× 10 workers）。

**设计决策**：
- **保留 line-based 外层 + char-based 内层**：fence 检测仍须依靠行边界；comment / CDATA 状态跨行必须 line-aware。比全 char-based 状态机代码量小、联成本低。
- **fixed-point loop 而非「完美一趟」**：“删后拼接”产生新 token 是抽象上不可变的现象（不是 stripper 逻辑 bug）。迭代到 fixed point 是唯一能保证 idempotence 的正确修法，且不损 content semantics。
- **嵌套 `<!-- <!-- --> -->`**：HTML5 规范不支持；第一个 `-->` 关闭。本实现镜像该行为（`strings.Cut(line, "-->")` 取首个），不实现真 depth tracking。
- **CDATA**：inCDATA 优先于所有其他 state；单行 CDATA 不特殊处理（因 inline 注释本来就 LEFT UNCHANGED，差异仅体现在跨行场景）。

**净代码量**：parse.go +90 / -10 行（包含大量 doc 与 fuzz 教训注释），parse_test.go +60 行（8 个新 case + 1 个 fuzz target + 13 corpus seeds）。

- **fence tag 不附 attrs**：fence 头是纯 `<untrusted-claude-md>`，header 行 "Contents of <PATH>:" 已显示路径。不重复 path/origin attrs，避免 Go `%q` 不转义 HTML 特殊字符造成的 fence-header 伪造面。
- **零宽空格 escape 而非 &lt;**：LLM 看到带 ZWSP 的标签仍可读（attacker payload 不丢语义），但不会被当作 fence 关闭。`&lt;` 转义在 markdown 里反而不自然。
- **上限只作用于 untrusted**：可信源（用户/管理员自寫）不受账本限制，爆炸面小。
- **fence 在聚合层走账本、在单源层走 escape**：责任拆分清晰，单源 render 可独立测试。
- **rune-aware truncate**：在 byte limit 位置退到上一个 UTF-8 rune 开始边界，避免 emoji / 中文 等多字节字符被切成非法 UTF-8 序列。
- **truncated 后仄货进入总量账本**：以 effective（= min(rawLen, single limit)）计。byte limit 是真上限：256 KiB ÷ 64 KiB single = 4 个满量源即触顶；count limit 32 是冗余 belt-and-suspenders ceiling，只在“大量超小源”这种 byte limit 迟迟不踩顶的 edge case 下生效。
