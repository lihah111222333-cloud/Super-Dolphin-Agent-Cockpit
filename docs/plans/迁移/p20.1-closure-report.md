## 3. 灰度评测 Runbook（shadow 阶段）

### 3.1 准备

1. 确认 `go build ./...` 在目标环境通过。
2. 确认 `ENABLE_SKILL_PROGRESSIVE_DISCLOSURE` 默认 `false`（当前仓库默认值）。
3. 确认 `skill.Service` 在目标进程的 fx graph 中已装载（否则 `RegisterSkillCatalogProviderIfEnabled` 会 warn 并跳过注册，flag 打开也无效）。

### 3.2 Shadow 打开步骤

```bash
# staging env
export ENABLE_SKILL_PROGRESSIVE_DISCLOSURE=true
export SKILL_CATALOG_TOKEN_BUDGET=3000      # 起始保守值；压测稳定后再考虑 4000/5000
export SKILL_CATALOG_META_INSTRUCTIONS=true # 保持 Phase 9 元指令在
```

启动进程后，日志应出现：

```
level=INFO msg=skill_catalog_provider.registered token_budget=3000 emit_meta_instructions=true
```

若看到：
- `reason=disabled` → flag 未生效，重检 env
- `reason=skill_service_unavailable` → fx optional injection 返回 nil，说明 skill 模块未装载，检查 `internal/module/skill.Module` 是否在 `app.Modules` 里

### 3.3 观测指标（需与应用埋点 / 未来 Prometheus exporter 对接）

在 shadow 期间至少监控一周，采集以下比率：

| 指标 | 期望值 | 告警阈值 |
|---|---|---|
| `skill_invalid_mode_total / turn_total` | 接近 0 | 任意非零都应调查，通常来自恶意或调包手工构造的 payload |
| `skill_untrusted_manifest_redaction_total / session_total` | 与仓库内 project skill 占比成正比 | 数量远超项目 skill 数 → 可能存在 skill 名喷洒/伪造 |
| `skill_trim_corruption_fallback_count` | 0 | >0 说明历史 rollout 出现新格式 block footer 缺失（上游写端 bug 或手改 rollout） |
| `skill_artifact_approval_miss_total` | 随审批 UI 接入后趋于下降 | Phase 1-11 未接入 UI 审批面，当前此值无下游消费 |
| `skill_expand_invoke_rate` | 随模型使用增长 | 持续为 0 说明 L1 manifest 没引导模型去调 tool，需检查元指令是否生效 |

### 3.4 Diff 采样（建议）

Shadow 期额外跑一条 A/B 日志线：对同一 turn 分别记录：

- **A**：Full body 注入（flag=off 的 legacy path）
- **B**：L1 manifest + on-demand expand（flag=on）

比较：
1. token 差值（目标：B < A，节省量随 skill 数量线性增长）
2. B 是否漏掉 A 里真正用到的 skill（目标：0）
3. B 是否误触发了 A 没用到的 skill（目标：接近 0）

### 3.5 回滚

一旦任一告警触发或模型质量劣化：

```bash
unset ENABLE_SKILL_PROGRESSIVE_DISCLOSURE   # 或显式设 false
# 重启进程即可回到全文注入
```

回滚等价于 flag=off：
- `skill_catalog` dynamic slot 未绑 provider → section 渲染为空
- `skill_expand_body` / `skill_read_resource` 工具仍走原 `skill.Service` 路径
- provider 写端的 pair-fenced block / Summary 分支（Phase 4）不受 flag 控制，继续按 `SkillRef.Mode` 自由渲染；不存在"回滚后 block 残留"的风险——现有 rollout trim（Phase 3）已覆盖这两种格式。
