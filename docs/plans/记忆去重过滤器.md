## 元信息

| 核心原则 | 全程静默、用户无感知、不影响 UI 手动写入、不影响 skill 自进化 |

## 设计摘要

在 Dream 和 Agent explicit 写入记忆前，插入一层静默去重过滤器：

1. **查重**：三级匹配（name 精确 / search_keys Jaccard ≥ 50% / 内容 containment ≥ 70%），同 type + 跨 scope
2. **决策**：完全相同 → 跳过；新 bigram 90%+ 在旧里 → 跳过；新独特 < 15% → 跳过；否则 → 合并
3. **合并**：偏好类按规则点 diff，项目类按段落级去重；旧内容为骨架，新增补入；frontmatter 合并（name 不变、search_keys 并集、description 取长）
4. **溢出控制**：同 type > 15 条 → 合并 containment 最高的一对（≥ 40% 才合并）；单条 > 1500 字符 → 截断最早段落
5. **skill 自进化保护**：FeedbackTracker.Record() 在去重检查之前执行，计数与写入解耦
6. **方式 A prompt 规则**：agent 对话中自动检测纠正/决策/不满信号，主动调 memory tool 保存

插入点：`service.go:290` 的 `writeIntent` 函数，覆盖所有 Dream + explicit 写入。UI 手动写入走 `applyUIMemoryUpsert`（ui_rpc_mutations.go），不经过过滤器。

```go
// Normalize 将原始记忆内容归一化为可比较的文本。
// 步骤：去 frontmatter（--- ... ---）→ 去 Markdown 格式符（#*->` ） → 全角转半角 → 去中英停用词 → 统一空白
func Normalize(raw string) string

// Bigrams 将归一化文本按 rune 拆分为 bigram 集合。
// 中文按相邻两字一组，英文单词视为整体 token 不拆 bigram。
// 返回 map[string]struct{} 去重集合。
func Bigrams(normalized string) map[string]struct{}

// Containment 计算包含系数 = |A∩B| / |shorter set|
func Containment(a, b map[string]struct{}) float64

// Jaccard 计算 Jaccard 相似度 = |A∩B| / |A∪B|
func Jaccard(a, b map[string]struct{}) float64
```

**中文停用词列表**（内联常量）：`的、是、在、了、把、被、和、与、或、不、也、都、要、会、到、就、这、那、有、个、为、上、中、下、让、从、对、已、但、而、之`

**英文停用词列表**：`the, a, an, is, are, was, were, be, been, to, of, in, for, on, with, at, by, and, or, but, not, this, that, it, its`

**验证**：
- `Normalize("---\nname: test\n---\n# 规则\n- 不要 **自动** commit")` → `"规则 自动 commit"`
- `Bigrams("记忆中心")` → `{"记忆", "忆中", "中心"}`
- `Containment({a,b,c}, {a,b,c,d,e})` → `1.0`（短集合 {a,b,c} 全在长集合里）
- 空集合安全处理（返回 0）

#### Task 1.2 — 三级重复匹配器

**文件**：`internal/module/memory/dedup/matcher.go`

```go
// EntrySnapshot 是去重比较用的条目快照。
// 字段与 shared.MemoryFrontmatter + MemoryEntry 一一对应，确保合并时不丢字段。
type EntrySnapshot struct {
    Name        string
    Type        string   // 当前类型字符串（feedback/project/user/reference）
    Description string
    SearchKeys  []string
    Lang        string   // 保留字段，合并时从旧条目继承
    Aliases     []string // 保留字段，合并时从旧条目继承
    Source      string   // "dream" / "" 等
    Content     string   // body 内容（不含 frontmatter）
    Path        string   // 磁盘全路径
    Scope       string   // "private" / "team"
}

// MatchResult 描述一次匹配结果。
type MatchResult struct {
    Found       bool
    Target      EntrySnapshot  // 匹配到的已有条目
    Level       string         // "name" / "search_keys" / "content"
    Score       float64        // containment 或 jaccard 值
}

// NormalizeName 将 name 归一化：小写 → 去标点 → 去连续空白 → trim。
func NormalizeName(name string) string

// FindDuplicate 在 existing 中找与 candidate 最匹配的条目。
// 三级匹配顺序：name 精确 → search_keys Jaccard ≥ 0.5 → content containment ≥ 0.7。
// 只在同 type 条目之间比较（跨 scope）。
// 返回最佳匹配，无匹配时 Found=false。
func FindDuplicate(candidate EntrySnapshot, existing []EntrySnapshot) MatchResult
```

**匹配逻辑**：
1. 过滤 `existing` 为同 `Type` 的子集
2. 遍历子集，先查 name 精确匹配（`NormalizeName` 后比较），命中立即返回
3. 未命中 name → 遍历查 search_keys Jaccard ≥ 0.5（双方都有 search_keys 才比较；注意：新写入的 candidate 由 `buildExplicitMemoryWrite` 构造，`MemoryWriteRequest` 无 SearchKeys 字段，因此此级匹配对新写入不会触发，只对 FindOverflowMerge 的已有条目间比较有效）
4. 未命中 search_keys → 遍历查 content containment ≥ 0.7
5. 如果多条命中 content，取 containment 最高的

**验证**：
- 同 type 同 name → 命中 level="name"
- 不同 type 同 name → 不命中
- search_keys `["language","chinese"]` vs `["language","chinese","communication"]` → Jaccard=2/3=67% → 命中
- 不同 type 高 containment → 不命中（跨 type 不比较）

#### Task 1.3 — 合并策略

**文件**：`internal/module/memory/dedup/merge.go`

```go
// Decision 表示去重决策。
type Decision int
const (
    WriteNew Decision = iota  // 无重复，正常写入
    Skip                      // 重复且无新增价值，跳过
    Merge                     // 重复但有新增内容，合并
)

// Decide 给定新旧条目的归一化 bigram 集合，返回决策。
//   完全相同 → Skip
//   新 bigram 90%+ 在旧里 → Skip
//   新独特 bigram < 15% of 新总量 → Skip
//   否则 → Merge
func Decide(oldBigrams, newBigrams map[string]struct{}) Decision

// MergeRulePoints 合并偏好类记忆（规则点 diff）。
// 将 old 和 new 的内容按行拆分，找出 new 中不在 old 里的行（bigram containment < 0.7），追加到 old 末尾。
func MergeRulePoints(oldContent, newContent string) string

// MergeParagraphs 合并项目类记忆（段落级去重）。
// 按空行拆分段落，new 段落与所有 old 段落的 containment < 0.5 → 追加；≥ 0.5 且更长 → 替换；否则保留旧段落。
func MergeParagraphs(oldContent, newContent string) string

// MergeContent 根据 type 选择合并策略。
//   type 含 "feedback"/"user" → MergeRulePoints
//   其他 → MergeParagraphs
func MergeContent(memType, oldContent, newContent string) string

// MergeFrontmatter 合并 frontmatter 字段，返回完整的 EntrySnapshot（只更新元数据，不改 Content）。
//   name: 保留 old
//   type: 保留 old
//   description: 取更长的
//   search_keys: 并集去重
//   lang: 保留 old
//   aliases: 保留 old
//   source: old 非 "dream" 时保留 old，否则取 new
func MergeFrontmatter(old, new EntrySnapshot) EntrySnapshot
```

**验证**：
- `Decide` 用实际数据：手写版 150 bigram vs dream 80 bigram 交集 72 → 72/80=90% → Skip
- `MergeRulePoints`：旧有 3 条规则 + 新有 4 条（3 重复 + 1 新增） → 结果 4 条
- `MergeParagraphs`：旧有 2 段 + 新有 1 段（重复）+ 1 段（新） → 结果 3 段
- `MergeFrontmatter`：search_keys 并集去重

#### Task 2.1 — DedupFilter 门面（纯决策，不执行写盘）

**文件**：`internal/module/memory/dedup/filter.go`

**核心原则：dedup 包只负责“决策”（查重 + 判定 + 内容合并），不负责“执行”（写盘 + 锁 + 验证 + 索引）。**

```go
// ScanFunc 是获取已有条目的回调，由调用方注入（避免 dedup 包依赖 store）。
type ScanFunc func(typeFilter string) ([]EntrySnapshot, error)

// Filter 是去重过滤器（纯计算，不持有写回调）。
type Filter struct {
    scanPrivate ScanFunc
    scanTeam    ScanFunc // 可为 nil（无 team 时）
}

func NewFilter(scanPrivate, scanTeam ScanFunc) *Filter

// CheckResult 是过滤检查结果。
type CheckResult struct {
    Action      Decision       // WriteNew / Skip / Merge
    MergedEntry *EntrySnapshot // Merge 时，已合并好的完整条目（含全部 frontmatter 字段 + 合并后的 content）
    TargetPath  string         // Merge 时，要覆盖的旧文件全路径
}

// Check 检查新条目是否重复，返回处理决策。
// 同 type + 跨 scope 查重。跨 scope 匹配时只跳过不合并（除非同 scope）。
func (f *Filter) Check(candidate EntrySnapshot) (CheckResult, error)

// OverflowInstruction 描述溢出合并指令（由调用方执行写盘）。
type OverflowInstruction struct {
    KeepEntry   EntrySnapshot // 保留的条目（内容已合并）
    DeletePath  string        // 要删除的条目文件路径
}

// FindOverflowMerge 检查指定 type 是否超过 MaxEntriesPerType。
// 超过且找到 containment ≥ 0.4 的 pair → 返回合并指令；否则返回 nil。
// 不执行写盘，由调用方在锁内执行。
func (f *Filter) FindOverflowMerge(memType string) (*OverflowInstruction, error)
```

**与旧设计的关键区别**：
- 去掉 `WriteFunc` / `DeleteFunc` 回调 — Filter 不再执行任何写盘操作
- `EnforceTypeLimit` 改为 `FindOverflowMerge`，只返回指令，不执行
- 所有写盘操作（锁 + 验证 + guard + 索引刷新）由 memory 包的调用方完成

**Check 流程**：
1. `scanPrivate(candidate.Type)` + `scanTeam(candidate.Type)` 获取所有同 type 已有条目
2. `FindDuplicate(candidate, allExisting)` 三级匹配
3. 无匹配 → `CheckResult{Action: WriteNew}`
4. 有匹配 →
   a. `Decide(oldBigrams, newBigrams)`
   b. Skip → `CheckResult{Action: Skip}`
   c. Merge 且同 scope → `MergeContent` + `MergeFrontmatter` → `CheckResult{Action: Merge, MergedEntry, TargetPath}`
   d. Merge 且跨 scope → `CheckResult{Action: WriteNew}`（不跨 scope 合并）

#### Task 2.2 — memory 包合并写入 helper

**文件**：`internal/module/memory/service.go`（新增函数，不新建文件）

封装合并写入逻辑，复用已有的锁 + 验证 + guard + 索引刷新：

```go
// mergeAndWriteMemory 将合并后的条目写入旧文件路径。
// 在 diskStoreLock 内执行：路径验证 → 内容验证 → 原子写入 → 索引刷新。
func mergeAndWriteMemory(store memoryWriteStore, targetPath string, merged MemoryEntry, options WriteOptions) error {
    if err := ValidateMemoryEntryContent(merged); err != nil {
        return err
    }
    root := store.Root()
    raw := formatMemoryEntry(merged)
    return withDiskStoreLock(root, func() error {
        validatedPath, err := ValidateMemoryWritePath(root, targetPath)
        if err != nil {
            return err
        }
        if err := writeAtomicFile(validatedPath, []byte(raw), 0o644); err != nil {
            return err
        }
        return updateIndexAfterMutation(root, options)
    })
}

// overflowMergeAndDelete 执行溢出合并指令：写合并结果 + 删被合并文件 + 刷索引。
// 在同一个 diskStoreLock 内完成，避免竞态。
func overflowMergeAndDelete(store memoryWriteStore, keepPath string, merged MemoryEntry, deletePath string, options WriteOptions) error {
    if err := ValidateMemoryEntryContent(merged); err != nil {
        return err
    }
    root := store.Root()
    raw := formatMemoryEntry(merged)
    return withDiskStoreLock(root, func() error {
        validatedKeep, err := ValidateMemoryWritePath(root, keepPath)
        if err != nil {
            return err
        }
        if err := writeAtomicFile(validatedKeep, []byte(raw), 0o644); err != nil {
            return err
        }
        validatedDel, err := ValidateMemoryWritePath(root, deletePath)
        if err != nil {
            return err
        }
        _ = os.Remove(validatedDel)  // best-effort delete
        return updateIndexAfterMutation(root, options)
    })
}

// snapshotToMemoryEntry 将 dedup.EntrySnapshot 转换为 MemoryEntry。
func snapshotToMemoryEntry(s dedup.EntrySnapshot) MemoryEntry {
    t := ParseMemoryType(s.Type)
    return MemoryEntry{
        Frontmatter: MemoryFrontmatter{
            Name:        s.Name,
            Description: s.Description,
            Type:        &t,
            Lang:        s.Lang,
            Aliases:     s.Aliases,
            SearchKeys:  s.SearchKeys,
            Source:      s.Source,
        },
        Content:  s.Content,
        FilePath: s.Path,
    }
}
```

**为什么这些 helper 放在 service.go 而不是新文件**：
- memory 主包 freeze limit=32，不能加文件
- `mergeAndWriteMemory` 需要访问包内部函数（`withDiskStoreLock`、`formatMemoryEntry`、`ValidateMemoryWritePath`、`writeAtomicFile`、`updateIndexAfterMutation`）
- `store` 参数类型是 `memoryWriteStore`（接口，有 `Root()` 方法），不是 `memoryStructuredStore`

#### Task 2.3 — 插入 writeIntent + 解耦 FeedbackTracker

**文件**：`internal/module/memory/service.go`

**改动 `writeIntent`（service.go:290）**：

```go
func (h *MemoryLifecycleHooks) writeIntent(ctx context.Context, threadID string, intent SaveIntent) error {
    // ① 无条件先计数（skill 自进化保护）
    trackFeedbackIfApplicable(h, intent)

    entry := buildExplicitMemoryWrite(intent)
    options := h.writeOptions(ctx, threadID)
    primary, secondary, err := h.intentDiskStores(ctx, threadID, entry.Type)
    if err != nil {
        return err
    }
    store, err := selectExplicitWriteStore(entry.Name, primary, secondary)
    if err != nil {
        return err
    }
    primaryScope, secondaryScope := scopeNamesForIntentStores(entry.Type, secondary != nil)
    h.warnCrossScopeSameName(entry.Name, store, primary, secondary, primaryScope, secondaryScope)

    // ② 去重检查
    if h.dedupFilter != nil {
        // 确定当前写入的 scope
        scope := primaryScope
        if store == secondary {
            scope = secondaryScope
        }
        candidate := dedup.EntrySnapshot{
            Name:        entry.Name,
            Type:        string(entry.Type),
            Description: entry.Description,
            Content:     entry.Body,
            Scope:       scope,
        }
        result, checkErr := h.dedupFilter.Check(candidate)
        if checkErr == nil {
            switch result.Action {
            case dedup.Skip:
                return nil  // 静默跳过
            case dedup.Merge:
                // 类型断言获取 Root()（所有 store 实际都是 *diskStore）
                ws, ok := store.(memoryWriteStore)
                if ok {
                    merged := snapshotToMemoryEntry(*result.MergedEntry)
                    if mergeErr := mergeAndWriteMemory(ws, result.TargetPath, merged, options); mergeErr == nil {
                        // 合并写入成功，跳过正常写入
                        h.handleDedupOverflow(ws, entry.Type, options)
                        return nil
                    }
                }
                // 合并失败 → fall through 到正常写入
            }
        }
        // checkErr != nil → 回退到正常写入（fail-open）
    }

    // ③ 正常写入
    if writeErr := upsertStructuredMemory(store, entry, options); writeErr != nil {
        return writeErr
    }

    // ④ 溢出控制（正常写入后也要检查）
    if h.dedupFilter != nil {
        if ws, ok := store.(memoryWriteStore); ok {
            h.handleDedupOverflow(ws, entry.Type, options)
        }
    }

    return nil
}

// handleDedupOverflow 检查并执行溢出合并。
func (h *MemoryLifecycleHooks) handleDedupOverflow(store memoryWriteStore, memType MemoryType, options WriteOptions) {
    instruction, err := h.dedupFilter.FindOverflowMerge(string(memType))
    if err != nil || instruction == nil {
        return
    }
    merged := snapshotToMemoryEntry(instruction.KeepEntry)
    _ = overflowMergeAndDelete(store, instruction.KeepEntry.Path, merged, instruction.DeletePath, options)
}
```

**关键设计决策说明**：

1. **为什么合并不走 `upsertStructuredMemory`**：
   - `MemoryWriteRequest` 没有 `SearchKeys`、`Source`、`Lang`、`Aliases` 字段，合并的元数据会丢失
   - `mergeAndWriteMemory` 直接操作完整的 `MemoryEntry`，通过 `formatMemoryEntry` 生成包含全部 frontmatter 字段的文件

2. **为什么要类型断言 `store.(memoryWriteStore)`**：
   - `selectExplicitWriteStore` 返回 `memoryStructuredStore`，没有 `Root()` 方法
   - `memoryWriteStore` 扩展了 `Root() string`，而所有 store 实际都是 `*diskStore`，实现了 `memoryWriteStore`
   - 断言失败时 fall through 到正常写入（fail-open）

3. **为什么合并写入在 `withDiskStoreLock` 内**：
   - 防止并发写入竞态
   - 复用 `ValidateMemoryWritePath` 做路径穿越防护（替代 guard）
   - 复用 `ValidateMemoryEntryContent` 做内容校验（确保 feedback 有 "Why:" 和 "How to apply:"）
   - `updateIndexAfterMutation` 在同一把锁内刷新 MEMORY.md 索引

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| memory 主包 freeze limit 32 | 不能在主包加文件 | dedup 逻辑在子包；helper 函数加在 service.go 内不新建文件 |
| scanMemoryEntries 性能 | 每次写入扫描磁盘 | 条目数 < 15，文件小，可接受；复用已有函数不引入新 I/O 路径 |
| dedup 子包不能导入父包 memory | 循环依赖 | dedup 只做决策（纯计算），`ScanFunc` 回调在 module.go 闭包中直接转换，不需要接口 |
| 合并写入跳过 upsertStructuredMemory | 可能绕过安全检查 | `mergeAndWriteMemory` 显式调用 `ValidateMemoryWritePath` + `ValidateMemoryEntryContent` + `withDiskStoreLock` |
| `memoryStructuredStore` 无 `Root()` | 合并时拿不到 store root | 类型断言为 `memoryWriteStore`，失败时 fall through 到正常写入 |
| 合并产生违和内容 | 用户看到不通顺的记忆 | MergeRulePoints 按行粒度操作，粒度足够细 |
| bigram 对英文单词的处理 | 英文单词不应拆 bigram | tokenizer 中英文单词视为整体 token |
| 过滤器故障阻塞写入 | 用户无法保存记忆 | fail-open 设计：Check 报错 / 合并失败 / 断言失败均 fall through 到正常写入 |
| trackFeedbackIfApplicable 前移 | 可能在写入失败时也计数 | 可接受，计数多一次不影响功能 |
| EntrySnapshot 字段丢失 | 合并后 Lang/Aliases 等字段消失 | EntrySnapshot 含全部 7 个 frontmatter 字段，`snapshotToMemoryEntry` 完整转换 |
| 溢出合并竞态 | 写合并 + 删旧文件非原子 | `overflowMergeAndDelete` 在同一个 `withDiskStoreLock` 内完成 |
