# gopls root cohort 契约（Phase A/B 最小稳定面）

`mcp-lsp` 的 gopls root cohort（Linux/macOS 使用 auto-remote，Windows 使用显式 loopback endpoint）由 canonical Git common-dir（非 Git 目录则使用规范绝对 root）标识。linked worktree 只要解析到同一个 common-dir，就必须进入同一个 root cohort；无关 root 不得复用该 cohort。

可信工作区集合是外部运行时配置，不是可编译进 `mcp-lsp` 的路径白名单。当前由 `GO_AGENT_LSP_ROOTS` / `GO_AGENT_LSP_ROOT` 注入；primary root 必须是显式绝对路径，附加 root 可以是绝对路径或相对 primary root 解析，缺失、显式为空或格式错误时 fail-fast，不得退回进程 CWD。canonical Git common-dir 只用于 cohort 身份归并，不扩大调用方已经授予的工作区访问边界，也不得把某台机器的可信工作区绝对路径写入源码或本契约。

入口层把 canonical root 转成 `multilsp.GoplsRepositoryInstanceProof`，再注入 `multilsp.GoplsRootCohortConfig`。配置的 `CohortID`、`RepositoryInstanceProof` 和 `EffectiveConfigDigest` 是单个配置代际内的 immutable admission 字段。同一 canonical root 仍有活跃 member、当前 drain owner 或历史 cleanup owner 时，第二份不同配置必须 fail-fast，不能并行创建第二个 cohort。只有在同一把跨进程锁内清理并证明旧 member 全部失效、且不存在未完成 owner cleanup 后，才允许保留单调递增的 epoch、journal revision、member generation 和 sequence，原子轮换到下一配置代际。

`AcquireLease` 返回成员级 `{Epoch, JournalRevision, MemberID, MemberGeneration, LeaseID}` fence。release 后旧 fence 必须被拒绝；同一配置重新准入只能复用原 cohort ID。

生产 controller 使用共享 LSP cache root 下的私有 `state.json`、member lease 记录和 flock；每个 admission/release/drain/config-generation transition 都在同一把跨进程锁内完成，并在记录写入/删除后同步父目录。owner lease 保存 PID 与启动身份，新的 admission 必须先按旧状态的 config digest 回收已退出或 PID 已复用的 stale member，再判断同代复用、活成员冲突或安全配置轮换，避免 sidecar 崩溃或宿主环境更新永久阻断该 root。

`EffectiveConfigDigest` 只记录会改变 gopls/Go 构建语义的稳定身份。gopls 和 `go` 使用解析后的真实路径与二进制内容摘要；显式 `CC`、`CXX`、`FC`、`AR`、`GCCGO`、`GOCACHEPROG`、`PKG_CONFIG` 同时绑定原命令与解析后工具的真实路径、内容摘要。`GOCACHE`、`GOMODCACHE`、`GOPATH`、`GOROOT` 未设置与显式设置为同一 `go` 二进制报告的默认值属于同一语义身份；真正偏离默认值的配置仍必须进入 digest。原始继承 `PATH` 不得直接进入 digest，未列入 Go 构建语义白名单的同前缀变量（例如 `GOOGLE_*`）也不得进入。Codex arg0 临时目录、重复 PATH 目录或不改变最终工具链解析结果的 PATH 顺序变化不得拆分 cohort；若 PATH 确实解析到不同的 gopls、Go 或显式辅助工具，则必须产生不同配置并服从上述代际准入规则。

Linux/macOS 的最后一个 member 释放时，state 记录 15 分钟 `IdleDeadline`、`DrainEpoch` 和 owner evidence。唯一 owner callback 负责关闭该 member 的 gopls forwarder；deadline 到达后先以 epoch/fence 二次复核，再执行 callback，成功写入 completion receipt。新的 admission 会在同一把锁内原子提升 epoch；跨 sidecar 不得被旧 owner 的 15 分钟 drain 阻断，而是把旧 fence 转入独立的 typed `PendingCleanups` journal。旧 sidecar 仍是该 fence 的唯一 cleanup owner，新 epoch 绝不执行旧 callback。callback 失败保留对应 fence 的 owner evidence、`cleanup_pending` 和 retry deadline；owner callback 不可达但 PID+start identity 仍精确存活时继续保留 pending 证据，绝不越权关闭旧 forwarder。不使用 RSS/ps 进程扫描或 kill 兜底。每次 admission 必须在同一持久锁内复核 current drain 与 pending cleanup owner：Darwin 绝对 start identity 严格早于 `kern.boottime`、owner PID 已退出，或 PID 仍存活但 start identity 已变化（PID 复用）时，原 owner 已被严格证明失效，可原子退役其 blocker；恢复路径不得发送任何信号，旧 gopls daemon 仍只按协议 idle timeout 自行退出。格式错误、不完整、权限/探测失败或仍精确存活的 owner evidence 必须保留并 fail-fast；没有等价 boot 证明的平台不得仅凭“可能发生过重启”退役 owner，但仍可使用 PID+start identity 的明确死亡/复用证明。

Darwin 没有可替代 pidfd 的外部稳定进程句柄，因此生产语言服务器必须由当前 `mcp-lsp` 二进制的内部 supervisor 作为独立 session/PGID leader 启动，真实 gopls forwarder 及其后代继承该 owner 组。`ProcessTree` 只能通过启动时创建且不传给真实语言服务器的专用控制管道请求 TERM/KILL；supervisor 只向自己的稳定 PGID 发信号，禁止从持久状态、`ps`、进程名或裸 PID 重建信号权限。父控制管道 EOF 是 exact owner 已消失的稳定证据；此外 supervisor 在 `PPID<=1` 且 CWD 明确返回 `ENOENT` 时必须自行启动 TERM→有界 KILL。权限、I/O 或其他不确定的 CWD 探测错误只记录 probe failure，不得授权信号。真实语言服务器退出后仍有同组后代时，supervisor 必须在自己退出前强制清空该组；外层只有在 `Wait`、`Remaining=0` 和 `Release` 全部收敛后才能完成 cleanup receipt。

进程内 `NewGoplsRootCohortController` 仍只提供测试/本进程冲突与 fence 证据，不能被描述成跨进程 authority；生产 runtime 必须注入 durable controller。

Linux 和 macOS 保持现有语义：同一 root cohort 使用 `-remote=auto;<cohortID>` 的 gopls 原生命名 endpoint，继续服从前述 durable admission、owner cleanup 和平台 `ProcessTree` 契约；本契约新增的 Windows broker、显式 TCP endpoint 与 Job 观测不得改变或替代这些路径。Linux/macOS 的生产 gopls 仍使用 `-remote.listen.timeout=15m` 作为协议级 idle timeout，产品 owner 只关闭其精确持有的 forwarder transport。

Windows 不使用 gopls native auto endpoint。同一 canonical Git repository instance（包括解析到同一 common-dir 的 linked worktrees）和同一配置代际只能存在一个 broker-owned 主 daemon；不同 `mcp-lsp` sidecar 各自启动独立 forwarder，并全部通过 durable `daemon.json` 中的规范 `tcp;127.0.0.1:<port>` endpoint 连接该 daemon。daemon 的唯一启动形态是受信 gopls 的 `serve -listen=tcp;127.0.0.1:<port> -listen.timeout=<idle>`，forwarder 只接收 `-remote=<explicit-loopback-endpoint>`，不得携带 daemon listen timeout。无关 root、不同配置代际或无法完整复核的 live record 不得复用。

Windows 的 daemon owner 是从当前 `mcp-lsp.exe` 精确 self-attest 后启动的 broker。sidecar 位于 `KILL_ON_CLOSE` Job 时，只有该 Job 明确允许 breakaway 才可把 suspended broker 脱离；broker 在恢复执行前必须再次复核 self 镜像路径、文件身份、启动身份和内容摘要，并确认自己不再位于 `KILL_ON_CLOSE` Job。broker 随后以私有 `ProcessTree` Job 启动清单固定、路径与 SHA-256 均已验真的包内 gopls，并在恢复 gopls 初始线程前完成 Job 绑定。broker 持有该 Job 的唯一精确 owner；已提交 daemon 不因任一 sidecar Job 关闭而退出，broker 退出或丢失 Job handle 时则由私有 `KILL_ON_CLOSE` Job 回收 gopls 及其后代。

Windows 禁止从 `PATH` 选择 gopls，禁止 `-remote=auto` / `-remote=auto;<name>`，也禁止在 bundle、manifest、摘要、durable cache、broker breakaway、endpoint 或身份校验失败时退回 PATH gopls、native auto、裸 forwarder 或独立 daemon。包内 manifest 和 bundle 路径必须由外部安装配置显式提供并与 `mcp-lsp` 安装根匹配；任何缺失或不一致都 fail-fast。

Windows 的启动发布是 durable lease 与 broker 两阶段提交。调用方先在 root 锁内取得 member lease；没有可复用 record 时启动 provisional broker/daemon，broker 以内部 wire schema v2 返回 owner、daemon、endpoint 与双 capability 证明但继续保留精确清理权限。父进程只有在 daemon endpoint ready、broker/daemon 身份与受信二进制复核、Job RSS 观测复核和 schema v4 `daemon.json` 原子写入并同步父目录全部成功后，才可发送绑定原 `ConfigDigest` 的 commit 并释放 provisional authority。commit 前的父 pipe EOF、超时或任一失败必须终止 broker 私有 Job、删除未完成发布并释放 lease；不得留下可被后续 admission 误认的半提交 record。

每个 Windows forwarder 关闭后立即释放自己的 durable lease。仍有 lease/forwarder 时主 daemon 保持服务；最后一份 lease 释放并且最后一个 forwarder 断开后，root owner 先执行下述零租约压力复核。RSS 未超限时 daemon 进入显式 `-listen.timeout` idle drain（生产默认 15 分钟），期间新的同配置 admission 复用原 daemon。idle deadline 后 daemon 按协议退出，broker 关闭观测端点、等待私有 Job 成员清零并释放 owner；失败证据继续按前述 durable cleanup 规则保留，禁止由新 epoch 越权接管旧 Job。

Windows `daemon.json` schema v4 在 endpoint、broker/daemon 启动身份和二进制摘要之外，必须持久化规范 loopback `observation_endpoint`、32 字节随机 `observation_capability` 和彼此不同的 32 字节随机 `reclaim_capability`。`observation_capability` 只接受 `observe_process_tree_rss`，返回绑定 `config_digest`、broker owner、daemon start identity、Job member PID 列表与聚合 RSS 的 `broker_process_tree_job` 快照；它不授予 signal、kill 或回收权限。`reclaim_capability` 只接受无 PID、路径、命令或参数的固定 `reclaim_process_tree` 方法；broker 以常量时间核对 capability 后，只能调用自身持有的 `ProcessTree.Terminate()`，并返回绑定同一 config、broker 与 daemon 身份的 `termination_accepted` 确认。两个 capability 交叉使用必须 fail-fast，且不得影响仍存活的 Job。该端点通过 broker 仍持有的私有 `ProcessTree` Job 枚举真实成员并求和，是 Windows 共享 gopls 唯一允许的树级 RSS 观测与回收 authority；不得以 daemon 单 PID RSS、`ParentProcessID` 遍历、进程名扫描、创建期上限或从 durable PID 重建 Job authority 代替。broker 本身和各 sidecar forwarder 不属于该 daemon Job，也不得计入主 daemon 树 RSS。

Windows broker Job 的树级 RSS 观测由唯一 root controller 在 admission 时消费；同一 `ConfigDigest`/`CohortID` 只发布一份 `resource.json`，并以 durable epoch 作为 generation。超限但仍有 active lease 时只记录 `defer_active_leases`，不得终止 broker、daemon、后代或 forwarder。所有 Windows lease 释放路径都先完成原 durable release，再重新取得同一 root filesystem lock：先统计当前 config 的 active lease，非零立即 no-op；零租约但 epoch 已变化也 no-op，由新 epoch 的 owner 负责。仅同 epoch、零租约、live `daemon.json` 身份可复核且 fresh Job RSS 仍超限时，才预先完整校验候选 receipt，使用独立 `reclaim_capability` 请求 broker 调用其 `ProcessTree.Terminate()`，严格校验 `termination_accepted` 后原子写入 `active_leases=0`、`decision=reclaim_zero_leases` 的 `resource.json`，最后 durable 删除 `daemon.json`。receipt 写入失败时不得退役 daemon record；record 退役失败时保留已写 receipt，后续同代重试只完成 record 退役。旧 repo resource cohort 已明确拒绝接管 gopls，不能重新启用第二个 controller。

manager/recycler 的 Go workspace idle 分支只接受 `multilsp.IdleReleasableClient.ReleaseForIdle`。生产 `goplsRootCohortClient` 同时声明 `IdleReleaseRequiredClient`；若 owner 接口缺失，recycler fail-closed、保留 `CleanupPending`，不回退到裸 `Client.Close`。

生产 gopls 创建链在 durable cache owner 初始化失败时 fail-fast。Linux/macOS 继续由原生命名 auto daemon 与 exact supervisor 承担既有生命周期；Windows 只允许 self-attested broker、显式 loopback endpoint 和私有 Job owner 路径。任何平台都不得把 RSS/进程扫描当作信号授权，也不得从持久化 PID 重建终止权限。
