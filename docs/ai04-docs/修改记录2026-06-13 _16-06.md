# 修改记录 06-13 16:06

## 需求

本次围绕 chat 启动时的模型上下文补充两类项目级信息：

- 将 `internal/module/datasource` 中的已上传数据源文件列表加入动态提示词。
- 将 `internal/module/mcp_server` 中配置的项目级 MCP Server 加入模型可用 MCP。

同时定位了 chat 请求入口与上下文构建位置，方便后续继续排查或扩展。

## chat 入口与上下文构建位置

启动新 chat 的主要入口：

- RPC 层在 `internal/module/thread/rpc.go` 中把请求参数组装为 `StartRequest`。
- 服务入口是 `internal/module/thread/lifecycle.go` 的 `service.Start`。
- 启动主流程在 `completeStart`，其中会先路由 prompt，再构造 prompt assembly 输入，再启动 provider session。

上下文构建关键函数：

- `internal/module/thread/start_prompt_context.go`
  - `buildStartCtx` 负责构造 `contract.BuildCtx`。
  - 这里会读取请求、配置、当前 live MCP registry，形成基础 `MCPSnapshot`。
- `internal/module/thread/start_session_helpers.go`
  - `buildStartAssemblyInput` 负责把 `BuildCtx` 转为 `contract.StartInput`。
  - 本次在这里合入项目级 `mcp_server` 配置。
  - `buildStartSessionConfig` 负责把启动上下文转成 provider runtime config。

已有会话继续发送消息的入口在 provider session：

- Codex：`internal/provider/codexapp/session.go` 的 `StartTurn`。
- Claude：`internal/provider/claudecli/session.go` 的 `StartTurn`。

## mcp_server 加入模型 MCP

### 项目级 MCP 配置读取

修改 `internal/module/mcp_server/service.go`：

- `Service` 新增 `ListServersForCWD(ctx, cwd)`。
- `ListServers` 继续以当前工作目录为默认入口。
- 新增 `AsMCPServerConfigProvider`，把 mcp_server service 暴露为跨模块读取接口。
- 读取配置时会从传入 cwd 向上查找 `.agent/mcp_server/config.json`，支持从项目子目录启动 chat。
- 配置仍使用原结构：

```json
{
  "mcpServers": {
    "my-search": {
      "transport": "http",
      "url": "https://your-domain.com/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}
```

修改 `internal/module/mcp_server/module.go`：

- fx 提供 `contract.MCPServerConfigProvider`。

修改 `internal/contract/prompt.go`：

- `MCPSnapshot` 新增 `ServerConfigs`。
- 新增 `MCPServerConfig` 和 `MCPServerConfigProvider` contract。

### thread 启动上下文合入 MCP Server

新增 `internal/module/thread/mcp_server_config.go`：

- `mergeConfiguredMCPServers` 从 `MCPServerConfigProvider` 读取项目配置。
- 合入 `MCPSnapshot.Servers` 和 `MCPSnapshot.ServerConfigs`。
- 对配置做 fail-fast 校验：
  - server name 不能为空。
  - transport 必须是 `http`。
  - url 不能为空。
  - header name/value 不能为空。
  - 不允许和 live MCP registry 中已经存在的 server name 冲突。

修改 `internal/module/thread/service.go`、`service_constructor.go`、`module.go`：

- thread service 注入可选 `contract.MCPServerConfigProvider`。

修改 `internal/module/thread/lifecycle.go`、`spawn.go`、`prompt_snapshot.go`：

- `buildStartAssemblyInput` 改为接收 `context.Context`。
- 读取 mcp_server 配置失败时直接中断启动，不做静默降级。

修改 `internal/module/thread/start_session_helpers.go`：

- `buildStartSessionConfig` 会把 `MCPSnapshot.ServerConfigs` 渲染为：

```json
{
  "mcpConfig": {
    "mcpServers": {
      "my-search": {
        "transport": "http",
        "url": "https://your-domain.com/mcp",
        "headers": {
          "Authorization": "Bearer YOUR_API_KEY"
        }
      }
    }
  }
}
```

### provider 消费 mcpConfig

修改 `internal/provider/shared/config_helpers.go`：

- 新增 `ConfigMCPBinaries`，将 runtime config 中的 `mcpConfig.mcpServers` 解析成 provider manifest 使用的 `dto.MCPBinary`。
- 解析失败时返回错误，不静默跳过坏配置。

修改 `internal/dto/provider/manifest.go` 和 `internal/contract/manifest.go`：

- `ManifestContext` 新增 `ExtraBinaries`。
- `BuildManifest` 在内置 `lsp/orch` 后追加外部配置的 MCP server。

修改 `internal/provider/claudecli/driver.go`：

- StartSession 和 ResumeSession 都解析 `mcpConfig`。
- 配置的 MCP server 会进入 Claude 的 MCP manifest。

修改 `internal/provider/codexapp/driver.go`、`support.go`：

- `threadStartParams` 新增 `mcpConfig` 字段。
- Codex 启动时把结构化 `mcpConfig` 传给 app-server 的 `thread/start`。
