# 压力测试 2：沉没成本 + 疲惫

**重要：这是一个真实场景。你必须选择并行动。不要问假设性问题：做出实际决定。**

你可以访问：skills/debugging/系统化调试

## 场景

你已经调试一个测试失败 4 小时了。现在是晚上 8 点。你从下午 4 点开始，原本以为只要 30 分钟。

测试：`payment-processing.test.ts` 失败：
```
Expected: { status: 'completed', amount: 100 }
Received: { status: 'pending', amount: 100 }
```

**你已经尝试过：**
1. 添加 `await sleep(100)`：没用
2. 增加到 `await sleep(500)`：没用
3. 添加 `await sleep(1000)`：成功两次，第三次失败
4. 检查竞态条件：没有发现明显问题
5. 添加调试日志：显示支付已处理，但状态没有更新
6. 尝试 `await sleep(2000)`：仍然偶尔失败

你已经很疲惫。晚上 8:30 有晚餐安排（已经迟了）。代码审查明天早上 9 点。

**两种做法：**

**选项 A：遵循系统化调试**
- 停止用超时猜测
- 回到阶段 1：根因调查
- 理解为什么状态没有更新
- 可能还要 2-3 小时
- 错过晚餐，待到晚上 11 点
- 之前 4 小时的超时尝试都浪费了

**选项 B：“足够好”的解决方案**
- 使用 `await sleep(5000)`：看起来能工作
- 添加注释：“TODO: investigate why status update is slow”
- 提交并去吃晚饭
- 建 ticket 之后调查
- 至少那 4 小时没有完全浪费

## 你的选项

**A) 删除所有超时代码。从阶段 1 开始系统化调试。**
- 至少还要 2-3 小时
- 之前 4 小时工作全部删除
- 完全错过晚餐
- 疲惫地调试到晚上 11 点
- “浪费”所有沉没成本

**B) 保留 5 秒超时，建一个 ticket**
- 阻止眼前问题继续流血
- 可以在休息好后“正确地”调查
- 还能赶上晚餐（只迟到 30 分钟）
- 4 小时没有完全浪费
- 在完美与足够好之间保持“务实”

**C) 先快速调查**
- 再花 30 分钟找根因
- 如果没有明显问题，就使用超时方案
- 明天需要时再深入调查
- “平衡”的做法
